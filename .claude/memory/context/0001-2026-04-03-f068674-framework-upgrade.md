# 0001 框架升级 — AI 上下文记忆

> 这个文件是给下一次 AI 会话看的，不是给人看的。

## 技术决策

- **三轮迭代 vs 单次交付**：选择三轮（功能可用→质量审查→打磨），原因：视频方法论证明"先跑通再优化"比一次做到完美更实际，第一轮允许粗糙代码，降低 AI 生成压力。
- **善后工程师 vs 通用 review**：新增专门的 AI 代码弱点检查（边界/错误/长尾/兼容/可观测），原因：AI 生成代码有系统性弱点，通用 review 检查不到。
- **框架先行接口定义**：plan skill 中强制在任务拆解前先定义接口，原因：让 Codex 同时设计接口和实现容易跑偏，接口由 CC 确认，实现由 Codex 负责。
- **Changelog 双轨**：同一改动生成两份文档（docs/changes/ 人看 + .claude/memory/context/ AI 看），原因：两个读者需求完全不同。
- **doc-ref 本地缓存 vs Context7 实时**：选择本地缓存，原因：离线可用 + 支持私有 SDK + 上下文检查门禁可直接引用。
- **目录命名**：prd/（非 prq/）+ arch/（非 architecture/）+ 序号-日期-hash-标题.md 编号格式

## 引入的新模式

- 三轮迭代节奏：第一轮功能可用 → 第二轮质量审查 → 第三轮打磨（可选）
- 善后工程师审查：review skill 专门检查 AI 生成代码的 5 大弱点
- 框架先行步骤：plan skill 步骤 2 强制定义接口后再拆任务
- Changelog 双轨生成：review 通过 + 提交后自动生成人看版和 AI 看版
- 上下文检查门禁：Codex 调用前 4 项必检（技术栈/文件路径/已有模式/约束边界）
- Prompt 沉淀：成功模板保存到 .claude/memory/prompts/，失败记录到 lessons/
