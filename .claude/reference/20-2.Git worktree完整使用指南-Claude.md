## 核心概念

### 什么是 Worktree

一个 Git 仓库可以同时 checkout 多个分支到不同目录，每个目录叫一个 **worktree**。各 worktree 共享同一份 `.git` 数据（objects、refs），但工作区文件完全独立、互不影响。

```
同一个 Git 仓库
├── main 分支    → /project/main/        ← worktree A
├── feature/x   → /project/feature-x/   ← worktree B
└── hotfix/y    → /project/hotfix-y/    ← worktree C
```

### Bare Repo 是什么

`git clone --bare` 只拉取 Git 元数据，不生成工作区文件。以它为中心，所有 worktree 平铺在项目根目录下，视觉最清爽，也最适合多工具并发。

### 关键约束

- 同一个分支**不能**同时被两个 worktree checkout
- stash 栈在所有 worktree 之间**共享**（重要！多工具并发时要注意）
- `.env`、`node_modules`、`venv` 等**不会**跨 worktree 自动共享

## 模式选择

```
需要多 AI 工具并发？
└── 是 → Bare Repo 模式（每个工具独占一个 worktree）

需要同时维护多个发布版本？（v1.x、v2.x）
└── 是 → Bare Repo 模式

单人开发，分支生命周期 < 1 周？
└── 是 → 临时分支模式（更简单）

对目录整洁度有强迫症？
└── 是 → Bare Repo 模式
```

| 特性 | 临时分支模式 | Bare Repo 模式 |
|------|------------|---------------|
| 初始化复杂度 | 低 | 中 |
| 目录整洁度 | ★★★☆☆ | ★★★★★ |
| 多 AI 并发支持 | 勉强可用 | ✅ 原生支持 |
| 多版本并行维护 | 不推荐 | ✅ 推荐 |
| 适合场景 | 短期功能、个人项目 | 团队协作、多工具、多版本 |

## 模式一：临时分支模式

### 目录结构

```
project-root/
├── .git/               ← 唯一的 git 仓库
├── src/
├── worktrees/          ← 所有临时 worktree 放这里
│   ├── feat-login/
│   └── fix-bug-123/
└── ...
```

### 初始化

普通 clone 即可，无需特殊操作：

```bash
git clone git@github.com:user/repo.git
cd repo
```

### 创建 Worktree

```bash
# 基于当前 HEAD 新建分支
git worktree add worktrees/feat-login -b feature/login

# 基于指定远端分支
git worktree add worktrees/fix-bug -b fix/bug-123 origin/main

# 基于 tag（用于 hotfix）
git worktree add worktrees/hotfix-v1 v1.2.0
```

### 完整工作流

```bash
# 1. 创建
git worktree add worktrees/feat-login -b feature/login

# 2. 进入开发
cd worktrees/feat-login
# ... 编码 → 测试 → commit ...
git add src/login.ts
git commit -m "feat: login page"
git push -u origin feature/login

# 3. 同步主分支（开发周期长时定期执行）
git fetch origin
git rebase origin/main

# 4. 合并回主分支
cd ../..
git merge --no-ff feature/login -m "feat: merge login"
git push origin main

# 5. 清理
git worktree remove worktrees/feat-login
git push origin --delete feature/login
git branch -d feature/login
```

## 模式二：Bare Repo 模式

### 目录结构

```
my-project/
├── .bare/          ← bare repo，所有 git 数据（隐藏）
├── .git            ← 文件，内容为 "gitdir: ./.bare"
├── main/           ← main 分支 worktree
├── v1.x/           ← 长期维护分支
├── feat-search/    ← 功能开发 worktree
└── claude-task-1/  ← Claude Code session 专用 worktree
```

`ls` 只看到干净的目录，`.bare` 和 `.git` 均隐藏。

### 初始化（新项目）

```bash
# 1. 创建项目根目录
mkdir my-project && cd my-project

# 2. Bare clone
git clone --bare git@github.com:user/repo.git .bare

# 3. 创建 .git 文件（注意：是文件不是目录）
echo "gitdir: ./.bare" > .git

# 4. 修复 fetch 配置（关键！不做这步分支名会显示错误）
git config -f .bare/config remote.origin.fetch "+refs/heads/*:refs/remotes/origin/*"

# 5. 拉取所有远端分支信息
git fetch origin

# 6. 创建 main worktree（先确认分支名）
git branch -a                        # 确认默认分支名
git worktree add main origin/main    # 明确指定来源
```

### 初始化（现有项目转换）

```bash
# 1. 在现有项目目录外创建新根目录
mkdir my-project-bare && cd my-project-bare

# 2. Bare clone 现有仓库
git clone --bare /path/to/existing-repo .bare

# 3. 创建 .git 文件
echo "gitdir: ./.bare" > .git

# 4. 修复 fetch 配置
git config -f .bare/config remote.origin.fetch "+refs/heads/*:refs/remotes/origin/*"
git config -f .bare/config remote.origin.url "git@github.com:user/repo.git"

# 5. 拉取远端信息
git fetch origin

# 6. 创建 main worktree（代码自动出现在 main/ 目录）
git worktree add main origin/main

# 7. 验证
ls main/   # 应该看到项目文件
git worktree list
```

> **不推荐**用 `mv` 手动迁移文件。让 `git worktree add` 自动 checkout 是最安全的方式。

### 日常创建 Worktree

```bash
# 基于 main 新建功能分支
git worktree add -b feature/search feat-search main

# 基于远端分支（已存在）
git worktree add feat-search origin/feature/search

# 基于 tag 做 hotfix
git worktree add hotfix-v1 v1.2.0

# 为 Claude Code session 创建专用 worktree
git worktree add -b claude/task-refactor claude-task-1 main
```

### 查看状态

```bash
# 在项目根目录执行
git worktree list

# 输出示例：
# /path/my-project/.bare              (bare)
# /path/my-project/main               abc1234 [main]
# /path/my-project/feat-search        def5678 [feature/search]
# /path/my-project/claude-task-1      abc1234 [claude/task-refactor]
```

## 多 AI 工具并发规范

这是原有文档缺失的核心内容，也是使用 worktree 最重要的场景。

### 基本原则

**每个 AI 工具 session 必须独占一个 worktree，严禁共用。**

```
Claude Code session 1  →  claude-task-1/   分支: claude/task-1
Claude Code session 2  →  claude-task-2/   分支: claude/task-2
Cursor                 →  cursor-feat/     分支: cursor/feat-x
你自己手动开发          →  main/ 或 feat-x/ 分支: feature/x
```

### 为什么必须独占

- 两个工具同时修改同一文件 → 后保存的覆盖前一个，无提示
- stash 共享 → 一个工具 stash push，另一个 stash pop 会拿错内容
- git hook 拦截的是命令级别，拦不住文件系统并发写入

### 标准的并发工作流

```bash
# ── 项目根目录 ──

# 给 Claude Code 开一个专用 worktree
git worktree add -b claude/refactor-auth claude-auth main
# → 告诉 Claude Code：你的工作目录是 ./claude-auth/

# 给 Cursor 开一个专用 worktree
git worktree add -b cursor/ui-redesign cursor-ui main
# → 在 Cursor 里打开 ./cursor-ui/ 目录

# 自己在 main 做日常工作
cd main
```

### 合并各工具产出

```bash
# 在项目根目录执行

# 1. 先看每个工具做了什么
git -C claude-auth log --oneline main..HEAD
git -C cursor-ui  log --oneline main..HEAD

# 2. 逐个合并（不要同时合并，一次一个，跑测试再下一个）
cd main
git merge --no-ff claude/refactor-auth -m "feat: merge claude auth refactor"
# 跑测试...
git merge --no-ff cursor/ui-redesign -m "feat: merge cursor ui redesign"

# 3. 清理已合并的 worktree
cd ..
git worktree remove claude-auth
git worktree remove cursor-ui
git branch -d claude/refactor-auth cursor/ui-redesign
```

### stash 共享问题的安全做法

因为 stash 栈所有 worktree 共享，多工具并发时**避免使用 stash 传递改动**，改用 patch 文件：

```bash
# 在 worktree A 中导出改动
git diff > /tmp/my-changes.patch

# 在 worktree B 中应用
git apply /tmp/my-changes.patch
```

## 日常操作手册

### 同步主分支到 feature worktree

在 feature worktree 里执行，不影响其他 worktree：

```bash
cd feat-search          # 进入目标 worktree
git fetch origin        # 拉取远端（所有 worktree 共享 objects，只需拉一次）
git rebase origin/main  # 变基到最新 main
# 如有冲突，解决后：
# git add <已解决文件>
# git rebase --continue
```

> `git fetch` 在任意 worktree 执行一次即可，其他 worktree 立即可见新的远端信息，因为共享同一份 `.git`/`.bare`。

### Cherry-pick 跨 worktree

```bash
# 把 hotfix worktree 里的某个 commit 应用到 main
cd main
git cherry-pick <commit-hash>

# 或者一次性挑多个
git cherry-pick abc123 def456
```

### 清理已完成的 Worktree

```bash
# 标准清理（有未提交改动会报错，安全）
git worktree remove feat-search

# 强制清理（丢弃未提交改动，谨慎）
git worktree remove -f feat-search

# 清理孤立记录（目录已手动删除但 git 记录还在）
git worktree prune -v

# 查看详细状态（脚本中使用）
git worktree list --porcelain
```

### 批量清理已合并的 feature worktree

```bash
# 列出已合并到 main 的分支，逐个清理
git branch --merged main | grep -E "^(feature|fix|claude|cursor)/" | while read branch; do
  dir=$(git worktree list --porcelain | grep -B2 "branch refs/heads/$branch" | grep "^worktree" | awk '{print $2}')
  [ -n "$dir" ] && git worktree remove "$dir" 2>/dev/null
  git branch -d "$branch"
  git push origin --delete "$branch" 2>/dev/null
  echo "cleaned: $branch"
done
```

## 依赖环境处理

新建 worktree 后，工作区文件独立，**依赖不会自动复制**，需要手动处理。

### Node.js / npm

```bash
cd feat-search

# 方案 A：独立安装（最干净，占磁盘）
npm install

# 方案 B：软链接共享 node_modules（节省磁盘，有风险）
ln -s ../main/node_modules ./node_modules
# ⚠️ 仅适合依赖完全相同的分支，依赖有差异时不要用
```

### Python / venv

```bash
cd feat-search

# 每个 worktree 建独立 venv
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 环境变量 / .env

`.env` 文件不会跨 worktree 共享（除非提交到 git，但通常不应该）：

```bash
# 从 main worktree 复制一份
cp ../main/.env .env
# 按需修改端口等本地配置
```

### 统一处理（推荐：写入 CLAUDE.md）

在 `CLAUDE.md` 里声明新建 worktree 后的初始化步骤，让 Claude Code 每次创建新 worktree 后自动执行：

```markdown
## Worktree 初始化

新建 worktree 后必须执行：
1. `npm install`（或 `pip install -r requirements.txt`）
2. `cp ../main/.env .env`
3. 确认测试通过：`npm test`
```

## 故障排除

| 问题 | 原因 | 解决 |
|------|------|------|
| `fatal: not a git repository` | 不在有 `.git` 文件/目录的路径下 | `cd` 到项目根目录或任意 worktree 内部 |
| `gitdir path does not exist` | `.bare` 被移动或重命名 | 修复 `.git` 文件中的路径：`echo "gitdir: ./.bare" > .git` |
| 分支名显示为 `(HEAD detached)` | `.bare/config` 缺少 fetch 配置 | `git config -f .bare/config remote.origin.fetch "+refs/heads/*:refs/remotes/origin/*"` 然后 `git fetch` |
| `worktree is already locked` | 上次操作中断 | `git worktree unlock <path>` |
| `already used by worktree` | 同一分支被两个 worktree 引用 | 先 remove 旧的：`git worktree remove <旧path>` |
| `git worktree add main` 失败 | 分支名不存在或 HEAD 指向不对 | `git branch -a` 确认分支名，再 `git worktree add main origin/main` |
| 残留记录（目录已手删） | 未正常 remove | `git worktree prune -v` |
| push 失败 `rejected` | 未设置 upstream | `git push -u origin <branch-name>` |
| 两个工具修改同一文件冲突 | 共用了同一个 worktree | 立即停止，各自退到独立 worktree，用 `git diff` 手动合并 |

### 修复损坏的 Worktree

```bash
# 查看详情
git worktree list --porcelain

# 尝试自动修复
git worktree repair

# 全量清理无效记录
git worktree prune -v
```
