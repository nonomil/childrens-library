## 安全红线

- **禁止自动删除/清理文件**：任何删除操作必须先告知用户，让用户决定。磁盘满等问题只分析不清理
- **禁止自动打包备份**：auto_checkpoint_commit.py 导致 16G 累积占满 D 盘。脏工作区只提示不自动打包

## 工作流硬约束

- **门禁是硬约束**：无论用户语气如何（"测试一下""试试""顺便""帮我改一下"），只要涉及代码改动必须走门禁
- **追问后必须汇报剩余任务**：回答用户追问后，主动输出 .claude/state/MANIFEST.yaml 中的未完成任务列表（Goal Drift 防护）
- **中途新需求独立走门禁**：对话中冒出的任何新功能需求，即使和当前任务相关，也必须独立走门禁流程
- **自动备份导致磁盘满**：脏工作区只提示不自动打包，让用户选择 A/B/C

## Codex 调用（可选辅助工具）

- **Codex 是辅助工具，不是默认执行器**：CC 自身编写代码，Codex 用于审查（`/codex:review`）、对抗审查（`/codex:adversarial-review`）、任务救援（`/codex:rescue`）
- **调用前检测可用性**：首次调用前检测 MCP 或插件是否可用。不可用则 CC 独立完成
- **重试导致上下文膨胀**：Codex 调用失败后不自动重试，向用户报告失败原因，由用户决定

## 用户偏好

- 中文回复，先结论后解释，删除操作必须先告知
- 遇到多方案时直接推荐最优解并说明理由
- 不想反复确认，涉及删除/清理文件必须先告知让用户决定

## 外部工具安装

- **install 命令会覆盖 settings.json hooks**：code-review-graph install 等外部工具的 install 命令会整体替换 hooks 字段而非合并。安装前必须 `git diff` 确认当前内容，安装后必须手动合并原有 hooks 与新增 hooks，禁止直接使用覆盖后的结果

## 方向漂移防护

- **工件驱动 > 对话信号驱动**：数"继续"次数容易误报。改为看 git diff、任务契约、基线哈希等客观工件，只在不完全确定时才调 LLM 判断
- **前提偏差会被放大**：用户说"当前扫描方法偏轻"，AI 顺着补测试→补实现→重构拆模块。每一步都合理，但前提本身有偏差。结果 scope 从"补字段"膨胀到"重构模块"。解法：工件驱动的独立审查（gate.md Rule E + direction-reviewer skill）
- **双方互相确认 = 双盲**：AI 认同用户前提→用户认同 AI 执行→双方都觉得"在正确方向上"→实际已走偏。解法：看客观工件而非对话信号
