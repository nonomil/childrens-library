# 审核技能

## 触发方式
- 由 `orchestrate` 调度流程调用
- 或用户说"审查当前改动" / "review"

## 审核标准

1. **逻辑正确性**：代码逻辑是否符合 plan.md 要求
2. **一致性**：与验收标准是否一致
3. **安全性**：无注入、越界、硬编码密钥等问题
4. **可测试性**：关键路径有测试覆盖
5. **代码风格**：命名规范、注释、缩进
6. **向后兼容**：不破坏现有 API 和用户代码
7. **善后工程师视角**：AI 生成代码通常在边界输入、错误处理、长尾情况有弱点，需要重点检查

## 善后工程师审查清单（AI 生成后必查）

> AI 生成的代码通常在以下地方需要人工补强。这些不要让 Codex 自己检查自己，由 CC 驱动确认。

- [ ] 边界输入（空值、超大值、非法格式）
- [ ] 错误处理（网络超时、文件不存在、并发冲突）
- [ ] 长尾情况（低概率但高影响的场景）
- [ ] 向后兼容（老调用方是否受影响）
- [ ] 日志和可观测性（出了问题能不能查）

## 审核输出格式

若通过：
```
[REVIEW_PASS] task_id: T00X
总结：实现符合预期，逻辑清晰
```

若不通过：
```
[REVIEW_FAIL] task_id: T00X
问题列表：
1. [严重] xxx 方法缺少边界检查
2. [建议] yyy 函数命名不清晰
修改要求：请针对以上问题修改后，回复 [FIX_DONE] + 修改摘要
```

## 轮次控制

每个任务最多审核 2 轮。第 2 轮仍不通过时：
- 记录到 `pipeline/review_log.md`
- 在 `pipeline/state.json.tasks` 中把该任务状态改为 `blocked`
- 同步加入 `blocked_tasks`
- 通知用户人工介入

## 审核记录

每次审核结果追加到 `pipeline/review_log.md`：

```markdown
## {日期} — T00X 审核

- 审核者：Claude Code
- 结果：PASS / FAIL
- 问题数：X
- 轮次：1/2
- 详情：...
```

若审核通过：

- 将对应任务状态更新为 `completed`
- 从 `pending_tasks` 中移除
- 同步加入 `completed_tasks`
