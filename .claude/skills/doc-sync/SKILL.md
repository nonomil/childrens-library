# 文档同步

核心原则：先确定真实变更面，再决定文档更新面。

## 何时使用

- 代码/配置改了参数入口、默认值、输出字段、控制逻辑或文件结构
- 用户说"代码改了，文档要同步""接口说明要更新"
- 需要判断"哪些文档必须改""先改哪份""哪些地方最容易漏"

## 文档盘点

| 文档类型 | 常见文件 | 要回答的问题 |
|---------|---------|------------|
| README / 总览 | `README.md` | 入口、运行方式、目录结构还对吗 |
| 接口文档 | API、输入输出说明 | 字段名、返回值、示例是否还有效 |
| 参数资料 | 默认配置说明 | 参数名、默认值是否仍正确 |
| 验证文档 | 测试说明、验证报告 | 结论是否仍与实现一致 |
| 集成说明 | 集成指南、迁移说明 | 上下游调用方式有没有变化 |

## 工作流

### 1. 把变更分类

- 参数与默认值变化
- 入口文件或加载顺序变化
- 输出字段或接口语义变化
- 算法行为变化
- 文件结构或目录结构变化

### 2. 做"变更 → 文档"映射

| 变更类型 | 必查文档 |
|---------|---------|
| 配置文件变化 | README、参数文档、示例命令 |
| 入口文件变化 | README、集成说明 |
| 输出字段变化 | 接口文档、验证文档 |
| 算法逻辑变化 | 方案文档、验证文档 |
| 目录结构变化 | README、引用路径示例 |

### 3. 只更新受影响段落

每份文档标记：必须改 / 建议改 / 可保留

### 4. 反向检查

- 还有没有文档继续引用旧入口或旧配置名
- 同一参数在多份文档里是否冲突

## 输出

| 输出 | 内容 |
|------|------|
| Stale Docs List | 哪些文档已过期，过期点是什么 |
| Update Priority | 先改哪些，后改哪些 |
| Change Map | 代码改动对应到哪些文档段落 |
| Validation Follow-up | 哪些验证需要补写或重跑 |
