# Industrial UI Design

## 概述

用工业软件的方式设计桌面界面，而不是用普通管理后台的方式堆控件。

优先保证三件事：操作员定位快、图像信息优先、长时间运行不疲劳。

## 适用场景

满足任一情况时使用本技能：

- 为机器视觉或工业检测软件设计主工作台
- 为 Qt / PySide / PyQt 桌面端补工业风布局和主题系统
- 需要把"图像居中、参数停靠、日志下沉"固化成规范
- 需要输出一套可复用的工业 UI 设计流程与检查清单

不适用于纯 Web 后台、营销站点或轻交互展示页。

---

## 核心流程

### 第 0 步：操作员任务分析（先于一切）

在动手设计之前，先回答：

1. 正常生产中，操作员每隔几分钟需要确认什么？
2. 出现异常时，操作员的处置流程是什么？
3. 换型或换品时，操作员需要修改哪些参数？
4. 每项关键操作，从当前页面出发最少需要几次点击？

目标：任何关键操作 ≤ 3 次点击可达。

### 第 1 步：确定信息层级

工业软件按操作粒度分为四级，设计前先明确每级的页面职责：

| 层级 | 定位 | 典型内容 |
|------|------|----------|
| L1 总览 | 快速扫描，感知全局 | 生产线状态、主要 KPI、当前告警汇总 |
| L2 区域 | 定位问题区域 | 工位 / 相机组状态 |
| L3 设备 | 日常操作主战场 | 单相机图像 + 参数 + 实时结果 |
| L4 诊断 | 深度排查与标定 | 算法调试、历史回溯、标定工具 |

页面之间保持一致的骨架，不因层级不同而破坏整体结构。

### 第 2 步：确定主工作台骨架

固定五层结构，不先做按钮细节：

1. 菜单栏
2. 左侧任务导航
3. 中央视图区（图像优先）
4. 右侧参数与动作面板
5. 底部运行区（日志 / 统计 / 最近结果）

### 第 3 步：确定主题系统

- 深色主题：用于值守与连续作业
- 浅色主题：用于调试、培训、截图

两套主题从第一天起同步维护，不留"只做深色"的技术债。

### 第 4 步：落页面职责

- 中间只放图像、状态、结果
- 右侧只放参数、动作、导出入口
- 底部负责过程记录，不取代中间结果区

### 第 5 步：补验证

- 线程不阻塞 UI
- 主题可切换
- 日志、统计、最近结果分区清晰
- 告警颜色未被用于装饰目的

## 设计规则

**布局**
- 以图像为中心，不把主界面做成表单墙
- 参数区必须停靠，不让输入控件挤占中央视图
- 所有页面遵守同一套骨架，不为单页破坏整体结构

**告警**
- 红色和黄色全局保留，专用于 NG / 报警 / 警告状态
- 不将告警色用于强调、装饰或品牌色
- 告警至少由两层信号构成：颜色 + 文本或图标
- 告警横幅固定可见，操作员切页时不丢失告警感知

**AI 推理结果**
- 不只显示分数；必须同时展示：缺陷类别 + 置信度 + 图像标注框
- 三者联动，操作员能直接判断是否需要复检
- 模型版本信息常驻状态栏

**线程与响应**
- 长时任务必须下放到后台线程，UI 始终保持响应
- 页面结果必须同步回流到日志与统计区

**外部接口**
- 参数来源解耦，不在 UI 层硬编码数据源
- 预留 MES / OPC-UA / IoT 对接接口
- 导出格式支持 JSON / CSV

---

## 交付物

至少输出以下内容：

- 信息层级说明（L1–L4 页面职责）
- 主窗口结构实现
- 深色 / 浅色两套主题
- 图像视图与基础工具条
- 底部日志 / 统计 / 最近结果分区
- 一份项目级 UI 规范文档

---

## 验证清单

- [ ] 是否定义了 L1–L4 信息层级，每级页面职责清晰
- [ ] 关键操作能否在 ≤ 3 次点击内从 L1 到达
- [ ] 是否存在 `文件 / 设置 / 说明` 菜单
- [ ] 是否保留左中右三栏与底部运行区
- [ ] 是否支持深色 / 浅色主题切换
- [ ] 告警颜色（红 / 黄）是否全局保留，未用于装饰
- [ ] 是否以 `QThread` 或等效机制处理长任务
- [ ] 若含 AI 推理，结果是否同时展示类别 + 置信度 + 标注框
- [ ] 参数来源是否与 UI 层解耦
