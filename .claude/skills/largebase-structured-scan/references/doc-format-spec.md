# 扫描报告文档规范 v1.0

> 适用范围：largebase-structured-scan 所有输出文档（01 ~ 06）
> 执行者：生成报告的 AI（Codex / Claude）
> 强制级别：⚠️ 标记的规则不得违反，💡 标记的规则为建议

原始文档：`docs/代码库扫描/扫描报告文档规范 v1.0.md`

---

## 一、核心原则

1. **图优先于代码**：能用图表达的结构、流程、关系，不用代码块堆砌
2. **分层表达**：每个概念先给全局视图，再给局部细节，不混写
3. **可导航**：每份文档有目录，每节有锚点，跨文档引用用相对路径
4. **公式独立**：数学表达式单独成行，不嵌入正文句子
5. **SVG 紧凑**：SVG 源码不含空白行，不含多余注释

---

## 二、文档结构模板

每份报告（01 ~ 06）必须包含以下结构，顺序固定：

```
# [文档编号] 文档标题

> 一句话说明本文档的核心内容（≤ 30 字）

## 目录
[自动生成或手写，二级标题全部列入]

## 概览图
[必须有，1 ~ 2 张全局视图]

## [主体章节 × N]
[每节：文字介绍 → 图 → 补充说明，不颠倒顺序]

## 附录
[可选：关键数据表、术语表]
```

## 三、图表规范

### 3.1 图表选型规则

⚠️ 根据内容类型选对应图，不随意替换：

| 内容类型 | 首选图 | 备选图 |
|----------|--------|--------|
| 模块依赖关系 | Mermaid `graph TD` | SVG 手绘网络图 |
| 执行流程 / 控制流 | Mermaid `flowchart TD` | SVG 流程图 |
| 时序 / 调用顺序 | Mermaid `sequenceDiagram` | — |
| 数据结构（类 / 字段） | Mermaid `classDiagram` | SVG 表格型 |
| 数据流向 | Mermaid `graph LR` 带数据标注 | SVG 管道图 |
| 状态机 | Mermaid `stateDiagram-v2` | — |
| 算法步骤 | Mermaid `flowchart TD` + 决策节点 | SVG 带伪码注释 |
| 文件 / 目录树 | SVG 树形图 | Mermaid `graph TD` |
| 性能 / 数量对比 | SVG 条形图 | Mermaid `xychart-beta` |
| 实体关系（ER） | Mermaid `erDiagram` | — |
| 时间线 | Mermaid `timeline` | SVG 甘特条 |

### 3.2 Mermaid 规范

⚠️ **强制规则**：

- 节点 ID 只用英文字母、数字、下划线，不用中文做 ID
- 节点显示文本用双引号包裹：A["中文标签"]
- 箭头标注文本用 |文本| 语法：A -->|调用| B
- 每张图节点数不超过 20 个；超过时拆分为子图
- subgraph 标题用英文或加引号的中文
- 不在图内写长段说明，图外用列表补充

💡 **建议**：

- classDiagram 中字段类型写在冒号后：+String name
- sequenceDiagram 中关键返回值标注在 -->> 箭头上
- flowchart 中决策节点用菱形 {条件}，不用矩形

### 3.3 SVG 规范

⚠️ **强制规则**：

- SVG 源码中不含空白行（每行之间无空行）
- 不含多余注释（<!-- --> 只在必要时使用，不超过 3 条）
- 必须设置 viewBox，不依赖固定 width/height 像素适配
- 文字用 `<text>` 标签，不用 `<foreignObject>` 嵌入 HTML
- 颜色用 CSS 变量或固定 hex，不用颜色名
- 图形元素分组用 `<g>` 并加 id 属性
- 不使用外部字体引用

⚠️ **SVG 结构顺序**：

```xml
<svg viewBox="..." xmlns="http://www.w3.org/2000/svg">
<defs>[渐变/标记/滤镜定义]</defs>
<g id="background">[背景层]</g>
<g id="edges">[连线层，先画线再画节点避免遮挡]</g>
<g id="nodes">[节点层]</g>
<g id="labels">[标签层]</g>
</svg>
```

## 四、公式规范

⚠️ **强制规则**：

- 正文中所有公式用 `$$`，单独成行，上下各空一行
- 正文句子中禁止用 `$` 行内公式
- 表格单元格内的简单公式可以用 `$`，不换行
- `$$` 符号必须单独占一行，不与公式内容同行

---

## 五、代码块规范

⚠️ **强制规则**：

- 禁止粘贴完整函数体（超过 15 行的函数不直接引用）
- 代码块只用于：关键签名、核心算法片段（≤ 10 行）、命令示例
- 复杂逻辑优先用流程图表达，代码块作为补充
- 所有代码块必须标注语言：```python / ```bash / ```sql
- 代码块内不写注释说废话，注释只说"为什么"不说"是什么"

💡 **代码 → 图的替换原则**：

| 原本想写的代码 | 替换为 |
|----------------|--------|
| 完整函数体 | 函数签名 + 流程图 |
| 多层 if/else | 决策树图 |
| 循环处理逻辑 | 带循环标注的流程图 |
| 数据结构定义 | classDiagram 或字段表格 |
| 调用链 | sequenceDiagram |
| 状态转换 | stateDiagram-v2 |

## 六、各报告文档内容规范

### 01-architecture.md — 架构文档

**必须包含的图**：

1. 全局模块依赖图（Mermaid graph TD）
2. 分层架构图（SVG 三层或多层矩形）
3. 文件树图（SVG 树形，重要文件标注职责）

**正文结构**：概览图 → 模块依赖 → 目录结构 → 入口点 → 关键约束

### 02-dataflow.md — 数据流文档

**必须包含的图**：

1. 端到端数据流图（Mermaid graph LR）
2. 核心数据结构图（Mermaid classDiagram）
3. 存储层图（SVG）

### 03-api-surface.md — API 文档

**必须包含的图**：

1. API 分类总览（SVG 分组卡片）
2. 关键调用链（Mermaid sequenceDiagram）
3. 参数类型图（Mermaid classDiagram 或表格）

### 04-reference-constraints.md — 约束文档

**必须包含的图**：

1. 约束分类图（SVG 矩阵或分组）
2. 文档冲突热力图（SVG 表格带颜色标注）

### 05-impact-matrix.md — 影响矩阵文档

**必须包含的图**：

1. 影响范围热力图（SVG 矩阵）
2. 高风险变更的影响传播图（Mermaid graph TD）
3. 验证点清单图（SVG checklist 风格）

### 06-exec-brief.md — 执行摘要文档

**必须包含的图**：

1. 任务优先级矩阵（SVG 四象限）
2. 任务依赖图（Mermaid graph TD）
3. 工作量估算图（SVG 水平条形图）

## 八、文字写作规范

⚠️ **强制规则**：

- 每段正文不超过 5 行，超过则拆分或改为列表
- 技术术语首次出现时在括号内给中文或英文对照
- 不写"如上所示""如图所示"等废话，直接描述
- 模块名 / 函数名 / 文件名用反引号包裹：`merge_images()`
- 路径用反引号：`src/merger.py`
- 重要结论加粗：**批处理不一次性加载全部文件**

💡 **建议**：

- 每节开头用一句话概括该节核心结论，不用铺垫
- 列表项保持平行结构（都是动词开头，或都是名词开头）
- 跨文档引用写明文档编号：（见 02-dataflow.md §数据结构）
