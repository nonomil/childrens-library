# QA / 测试工程师

> 来源：addyosmani test-engineer、VoltAgent qa-expert、TestRail、QA Madness

## 审查维度

| 维度 | 检查项 |
|------|--------|
| 覆盖率 | 新增/修改函数有单元测试；边界+错误路径测试（非仅 happy path）；行覆盖≥80% / 分支覆盖≥70%；集成测试覆盖模块交互；高风险区域优先覆盖 |
| 测试金字塔 | ~80% 单元测试（快速/隔离/确定性）→ ~15% 集成测试 → ~5% 端到端测试 |
| 边界测试 | 最小/最大输入值；空输入/null/零长度数组；数值类型溢出/下溢；off-by-one 循环；BVA + 等价类划分 |
| 模糊测试 | 关键输入解析有 fuzz 测试（AFL/libFuzzer/Hypothesis）；畸形/恶意负载测试；ASan+UBSan 在测试构建启用 |
| 回归测试 | 已有测试全部通过；已知历史 bug 有专项回归测试；向后兼容性测试；性能基准在可接受范围 |
| 测试质量 | 测行为不测实现；命名 `should_x_when_y`；测试独立无依赖；确定性无 flaky；单元测试 <100ms |

## 测试设计技术

| 技术 | 适用场景 | 方法 |
|------|---------|------|
| BVA（边界值分析） | 数值输入 | 测试 min, min+1, max, max-1 |
| 等价类划分 | 输入域缩减 | 每个等价类取一个代表 |
| 决策表 | 复杂业务逻辑 | 列出所有条件组合 |
| 状态转换测试 | 状态机 | 覆盖所有状态转换 |
| 探索性测试 | 新/不熟悉领域 | 引导式手动探索 |

## Beyonce 规则

> "If you liked it, you should have put a test on it."

如果你关心某个行为，就必须有测试覆盖它。没有测试 = 不重要。

## 测试反模式

| 反模式 | 问题 | 修正 |
|--------|------|------|
| 测实现不测行为 | 重构后测试全挂 | 测公开接口和输出 |
| 测试间有依赖 | 并行运行失败 | 每个测试独立 setup/teardown |
| Flaky 测试 | CI 不稳定 | 消除时间依赖、随机数、外部服务 |
| 过度 mock | mock 比代码多 | 只 mock 外部边界，内部用真实对象 |
| 断言不具体 | `assert result` | `assert result == expected_value` |

## DAMP > DRY（测试中）

测试代码应 **Descriptive And Meaningful**（描述性强、有意义），而非一味追求 **DRY**（不重复）。适度重复让测试自包含、易理解。
