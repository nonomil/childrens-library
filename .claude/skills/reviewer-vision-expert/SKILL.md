# 机器视觉 / 图像处理专家

> 来源：OpenCV Coding Style Guide、OpenCV 官方文档、工业视觉实践

## 审查维度

| 维度 | 检查项 |
|------|--------|
| 数值精度 | 中间计算用 `CV_32F`/`CV_64F`（即使输入输出为 `CV_8U`）；FP16/FP32 权衡；整数溢出检查；归一化一致性；浮点比较容差定义；除零保护 |
| 算法正确性 | 核大小验证（奇偶要求）；步长/填充参数验证；坐标系一致性（像素中心 vs 角点约定）；ROI 不越界；相机标定参数范围验证；单应性矩阵数值稳定性 |
| 实时性能 | 最小化图像克隆/拷贝；ROI 操作替代子图创建；用 in-place 操作；SIMD/GPU 加速（UMat/CUDA）；逐帧计时剖析瓶颈；避免热路径内存分配 |
| I/O 健壮性 | 格式处理（PNG/JPEG/BMP/TIFF）；色彩空间转换验证（BGR vs RGB）；空图/零尺寸输入处理；损坏文件不崩溃 |
| OpenCV 最佳实践 | `cv::Mat` 替代 `IplImage`；操作前 `mat.empty()` 检查；类型安全用 `cv::Mat_<T>`；避免不必要的 `clone()` |
| 测试覆盖 | 真实+对抗性图像测试集；Ground Truth 对比；像素级精度断言 |

## 常见陷阱清单

1. **cos^n 角度校正缺失**：测量值需除以 cos(θ)^n 校正透视缩短，n 取决于测量维度（一维 cos、二维 cos²、三维 cos³）
2. **BGR vs RGB**：OpenCV 默认 BGR，matplotlib/PIL 默认 RGB，混用会导致颜色错误
3. **CV_8U 溢出**：`uint8` 加法溢出归零，中间计算必须用浮点
4. **`clone()` 滥用**：每次 clone 复制整幅图像内存，热路径中是性能杀手
5. **ROI 越界**：`Rect` 超出图像边界会抛异常或静默截断
6. **`imread` 静默失败**：文件不存在返回空 Mat，不抛异常 → 必须检查 `empty()`

## 数值精度检查要点

- 累加操作用 `CV_64F` 防精度丢失
- 除法前检查分母非零
- 浮点比较用 `abs(a-b) < epsilon`，不用 `==`
- 归一化前后数据范围一致
- 三角函数输入角度/弧度单位统一
