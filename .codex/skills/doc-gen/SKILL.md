# 结构化文档生成技能

## 模式识别与触发

> 用户请求或流程输出需要生成正式文档时，按关键词匹配文档模式。匹配优先级从上到下。

| 模式 | 触发关键词 | 典型场景 | 首选图表 |
|------|-----------|---------|---------|
| **scan** | 结构化扫描/扫描报告/先扫描 | largebase 01-06 扫描包 | 见 `largebase-structured-scan/references/doc-format-spec.md` §六 |
| **report** | 报告/测试结果/审查结果/分析报告/运行结果 | 测试报告、审查报告、分析报告 | 状态表格、SVG 条形图、`timeline` |
| **design** | 设计文档/方案/选型/对比/架构决策/技术路线 | 新功能设计、架构方案、技术选型 | SVG 四象限、`flowchart`、SVG 甘特条 |
| **change** | 总结/梳理/汇总/变更/改了什么/diff 总结/修改点 | 变更总结、版本回顾、会议结论 | SVG 热力图、`flowchart LR`、`graph TD` |
| **explain** | 看不懂/解释/说明/怎么工作/什么意思/帮我理解/讲一下 | 理解代码、架构、流程 | `graph TD`、`flowchart`、`sequenceDiagram` |

**不适用**：纯文本回复（问答、闲聊）、单行注释、commit message、PR description。

**优先级冲突处理**：scan > report > design > change > explain；无法判断时默认 explain。

---

## 通用规则（所有模式共用）

### 核心原则

1. **图优先于代码**：能用图表达的不用代码块堆砌
2. **分层表达**：先全局视图再局部细节
3. **可导航**：有目录，有锚点，跨文档引用用相对路径
4. **一句话开头**：每份文档/每节开头一句话概括核心结论（≤ 30 字）

---

### 图表选型

| 内容类型 | 首选图 | 备选图 |
|----------|--------|--------|
| 模块依赖 / 层次 | `graph TD` | SVG 网络图 |
| 执行流程 / 控制流 | `flowchart TD` | SVG 流程图 |
| 时序 / 调用顺序 | `sequenceDiagram` | — |
| 数据结构 | `classDiagram` | SVG 表格型 |
| 数据流向 | `graph LR` 带格式标注 | SVG 管道图 |
| 状态机 | `stateDiagram-v2` | — |
| 决策 / 算法 | `flowchart TD` + 菱形 | SVG 带伪码 |
| 文件 / 目录树 | SVG 树形图 | `graph TD` |
| 数量对比 / 性能 | SVG 条形图 | `xychart-beta` |
| 实体关系 | `erDiagram` | — |
| 时间线 / 里程碑 | `timeline` | SVG 甘特条 |
| 影响范围 / 热力 | SVG 矩阵色块图 | — |
| 优先级排布 | SVG 四象限 | — |

### Mermaid 规范

⚠️ **强制规则**：

- 节点 ID 只用英文字母、数字、下划线：`A["中文标签"]`
- 箭头标注用 `|文本|`：`A -->|"调用"| B`
- 每张图节点 ≤ 20；超过时拆分 subgraph
- subgraph 标题用英文或加引号的中文
- 图内不写长段说明，图外列表补充
- `classDiagram` 字段类型写在冒号后：`+String name`
- `sequenceDiagram` 关键返回值标注在 `-->>` 箭头上

---

### SVG 规范

⚠️ **强制规则**：

- SVG 源码中**不含空白行**（每行之间无空行）
- 注释 `<!-- -->` 只在必要时使用，不超过 3 条
- 必须设置 `viewBox`，不依赖固定 `width`/`height` 像素适配
- 文字用 `<text>` 标签，不用 `<foreignObject>` 嵌入 HTML
- 颜色用固定 hex（如 `#4a9edd`），不用颜色名（避免渲染差异）
- 图形元素分组用 `<g>` 并加 `id` 属性
- 不使用外部字体引用

⚠️ **SVG 结构顺序**（固定，不可调换）：

```xml
<svg viewBox="..." xmlns="http://www.w3.org/2000/svg">
<defs>[渐变 / 标记 / 滤镜定义]</defs>
<g id="background">[背景层]</g>
<g id="edges">[连线层，先画线再画节点避免遮挡]</g>
<g id="nodes">[节点层]</g>
<g id="labels">[标签层]</g>
</svg>
```

**SVG 最小示例（三层架构）**：

```xml
<svg viewBox="0 0 600 300" xmlns="http://www.w3.org/2000/svg">
<defs>
<marker id="arr" markerWidth="8" markerHeight="8" refX="6" refY="3" orient="auto">
<path d="M0,0 L0,6 L8,3 z" fill="#555"/>
</marker>
</defs>
<g id="background">
<rect x="20" y="20" width="560" height="70" rx="8" fill="#e8f4fd" stroke="#4a9edd" stroke-width="1.5"/>
<rect x="20" y="110" width="560" height="70" rx="8" fill="#e8fde8" stroke="#4add6a" stroke-width="1.5"/>
<rect x="20" y="200" width="560" height="70" rx="8" fill="#fdf5e8" stroke="#ddaa4a" stroke-width="1.5"/>
</g>
<g id="edges">
<line x1="300" y1="90" x2="300" y2="108" stroke="#555" stroke-width="1.5" marker-end="url(#arr)"/>
<line x1="300" y1="180" x2="300" y2="198" stroke="#555" stroke-width="1.5" marker-end="url(#arr)"/>
</g>
<g id="nodes"/>
<g id="labels">
<text x="300" y="50" text-anchor="middle" font-size="13" font-weight="bold" fill="#1a5f8a">入口层</text>
<text x="300" y="140" text-anchor="middle" font-size="13" font-weight="bold" fill="#1a7a2a">核心层</text>
<text x="300" y="230" text-anchor="middle" font-size="13" font-weight="bold" fill="#7a4a1a">IO 层</text>
</g>
</svg>
```

### 公式规范

⚠️ **强制规则**：

- 正文中所有公式用 `$$`，**单独成行**，上下各空一行
- 正文句子中**禁止**用 `$` 行内公式
- `$$` 符号**必须单独占一行**，不与公式内容同行
- 表格单元格内的简单公式可以用 `$`，不需要换行

**正确示例**：

```markdown
批量处理的时间复杂度为：

$$
T(n) = O(n \cdot k)
$$

其中 n 为文件总数，k 为单文件平均处理时间。
```

**错误示例**：

```markdown
<!-- ❌ 错误：$ 行内，与文字混排 -->
时间复杂度为 $T(n) = O(n \cdot k)$，其中 n 为文件数。

<!-- ❌ 错误：$$ 与公式同行 -->
时间复杂度为 $$T(n) = O(n \cdot k)$$。
```

**表格内公式**（正确，无需换行）：

| 指标 | 公式 | 说明 |
|------|------|------|
| 时间复杂度 | $O(n \cdot k)$ | n 文件数，k 单次耗时 |

---

### 代码块规范

⚠️ **强制规则**：

- **禁止**粘贴完整函数体（> 15 行的函数不直接引用）
- 代码块只用于：关键签名、核心算法片段（≤ 10 行）、命令示例
- 复杂逻辑**优先用流程图表达**，代码块作为补充
- 所有代码块必须标注语言：` ```python ` / ` ```bash ` / ` ```sql `
- 注释只说"为什么"，不说"是什么"

**代码 → 图替换原则**：

| 原本想写的代码 | 替换为 |
|----------------|--------|
| 完整函数体 | 函数签名 + 流程图 |
| 多层 if/else | 决策树图（`flowchart TD` + 菱形） |
| 循环处理逻辑 | 带循环标注的流程图 |
| 数据结构定义 | `classDiagram` 或字段表格 |
| 调用链 | `sequenceDiagram` |
| 状态转换 | `stateDiagram-v2` |

---

### 文字规范

⚠️ **强制规则**：

- 每段正文不超过 5 行，超过则拆分或改为列表
- 技术术语首次出现时在括号内给中英文对照
- 不写"如上所示""如图所示"等废话，直接描述
- 模块名 / 函数名 / 文件名 / 路径用反引号包裹：`` `merge_images()` ``
- 重要结论加粗

💡 **建议**：

- 每节开头用一句话概括该节核心结论，不用铺垫
- 列表项保持平行结构（都动词开头，或都名词开头）
- 跨文档引用写明文档编号：（见 `02-dataflow.md` §数据结构）

## 模式专用模板

### Mode: explain（解释型）

> 目标：让读者理解代码/架构/流程，不假设前置知识。

**必须包含**：
- 至少 1 张架构/依赖图（`graph TD` 或分层 SVG）
- 至少 1 张核心流程图（`flowchart` 或 `sequenceDiagram`）

**结构模板**：

```markdown
# [模块/功能名] 说明文档

> 一句话概括该模块的核心职责（≤ 30 字）

## 目录

## 全局视图
[架构图 / 分层图 / 模块依赖图]
[一句话总结整体结构]

## 核心概念
[关键实体/概念列表，每个一句话]

## 工作流程
[核心业务流程图]
[关键步骤的文字补充]

## 入口与接口
[入口点列表：路径 → 触发方式 → 调用链 Top3]
[公开接口表格：函数名 | 签名 | 说明]

## 关键细节
[复杂逻辑的流程图或状态图]
[注意事项列表]

## 附录（可选）
[术语表]
```

**explain 专有规则**：
- 不假设读者有前置知识，术语首次出现必须解释
- 每个概念先给直觉解释再给技术细节
- 调用链图标注数据格式：`A -->|"List[Path]"| B`

---

### Mode: report（报告型）

> 目标：数据驱动，结论明确，失败项可追溯。

**必须包含**：
- 至少 1 张状态总览表或指标对比图
- 明确的 PASS / FAIL / PARTIAL 结论标记

**结构模板**：

```markdown
# [报告类型] 报告

> 一句话总结核心结论（≤ 30 字）

## 目录

## 执行摘要
[结论：PASS / FAIL / PARTIAL]
[关键指标表格：总数 | 通过 | 失败 | 跳过 | 覆盖率]

## 详细结果
[各任务/用例状态表格]
[失败项详情列表]

## 趋势与对比（可选）
[前后对比 SVG 条形图或表格]

## 风险与建议
[Top N 风险列表：描述 | 触发条件 | 缓解措施]

## 附录
[原始数据 / 日志摘要]
```

**report 专有规则**：
- 结论先行，不放最后
- 数字必须对得上：总数 = 通过 + 失败 + 跳过
- 失败项必须可追溯（文件 / 函数 / 用例名）
- 审核轮次 > 1 时标注每轮变化

---

### Mode: change（变更型）

> 目标：突出 before/after，列明影响范围，绑定验证点。

**必须包含**：
- 至少 1 张影响传播图（`graph TD`）或影响热力图（SVG 矩阵）
- 每个变更点绑定验证清单

**结构模板**：

```markdown
# 变更总结：[主题]

> 一句话概括本次变更的核心目的（≤ 30 字）

## 目录

## 变更概览
[变更点数量 | 涉及文件数 | 影响范围：全局/模块/函数级]
[影响传播图或热力图]

## 变更明细
[表格：变更点 | 文件 | 类型（新增/修改/删除）| 风险等级]

### [变更点 1]
[前后对比说明]
[影响范围列表]
[验证点清单]

## 影响分析
[受影响模块表格：模块 | 直接影响 | 间接影响 | 需验证]

## 验证清单
[每条：验证项 | 对应变更点 | 验证方式 | 状态]
```

**change 专有规则**：
- 每个变更点必须有风险等级（high / medium / low）
- high 风险变更必须有独立的传播图和验证清单
- 不遗漏间接影响（依赖方、调用方）

---

### Mode: design（设计型）

> 目标：呈现决策过程和理由，方案有对比有结论。

**必须包含**：
- 至少 1 张方案对比图（SVG 四象限或对比表格）
- 至少 1 张实现架构图（`graph TD` 或分层 SVG）

**结构模板**：

```markdown
# [功能/模块] 设计文档

> 一句话概括设计目标（≤ 30 字）

## 目录

## 背景与目标
[问题陈述]
[目标列表，每个可验证]

## 方案对比
[候选方案表格：方案 | 优势 | 劣势 | 适用场景]
[SVG 四象限图或雷达图]
[决策结论 + 理由]

## 架构设计
[整体架构图]
[模块职责表格]
[核心数据流图]

## 接口定义
[公开接口表格：函数 | 签名 | 说明 | 兼容策略]
[调用链 sequenceDiagram]

## 实现计划
[任务拆分表格：任务 | 依赖 | 复杂度 | 路由建议]
[任务依赖图 Mermaid]
[里程碑时间线]

## 风险与约束
[技术风险列表]
[约束条件列表]
[回滚方案]
```

**design 专有规则**：
- 方案对比必须给出"建议采用 + 理由"，不能只列不选
- 接口定义必须标注兼容策略（新增参数需默认值等）
- 每个任务必须标注路由建议（complex / parallel / debug）

---

### Mode: scan（扫描型）

> largebase-structured-scan 专用，输出 01-06 扫描包。

**不使用本模板**，直接遵循 `largebase-structured-scan/references/doc-format-spec.md` 中各文档的专用规范。
所有通用规则（SVG、Mermaid、公式、代码块、文字规范）同样适用。

扫描型额外约束（图表数量下限）：

| 文档 | 最少图数 | 推荐图数 |

| 01-architecture | 3 | 4 ~ 5 |
| 02-dataflow | 3 | 4 ~ 6 |
| 03-api-surface | 2 | 3 ~ 4 |
| 04-reference-constraints | 2 | 3 |
| 05-impact-matrix | 3 | 4 ~ 5 |
| 06-exec-brief | 3 | 3 ~ 4 |

## 校验清单（生成后自查）

### 通用项

```
[ ] 有标题 + 一句话说明（≤ 30 字）
[ ] 有目录（文档 > 100 字时）
[ ] 有至少 1 张概览图
[ ] 正文顺序：文字 → 图 → 说明

Mermaid
[ ] 节点 ID 不含中文
[ ] 节点数 ≤ 20（超过已拆 subgraph）

SVG
[ ] 设了 viewBox
[ ] 源码无空白行
[ ] 无 <foreignObject>
[ ] 结构顺序：defs → background → edges → nodes → labels

公式
[ ] 正文中无 $ 行内公式（表格内除外）
[ ] $$ 单独占一行，未与公式内容同行

代码块
[ ] 无完整函数体（> 15 行）
[ ] 所有代码块已标注语言

文字
[ ] 每段 ≤ 5 行
[ ] 模块名/函数名/路径用反引号
[ ] 无"如上所示"等废话
```

### 模式专属项

```
explain:
[ ] 有架构/依赖图
[ ] 有核心流程图
[ ] 术语首次出现已解释

report:
[ ] 有明确结论（PASS / FAIL / PARTIAL）
[ ] 数字能对得上（总 = 通过 + 失败 + 跳过）
[ ] 失败项可追溯到文件/函数名

change:
[ ] 每个变更点有风险等级
[ ] high 风险有传播图 + 验证清单
[ ] 间接影响已列出

design:
[ ] 方案有对比有结论（不能只列不选）
[ ] 接口有兼容策略

scan:

[ ] 各文档图类型符合 `largebase-structured-scan/references/doc-format-spec.md` §六
```
