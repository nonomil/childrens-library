# 工业软件 UI 设计手册

## 1. 适用范围

本手册适用于以下桌面系统：

- 机器视觉检测
- 工业相机采图与回放
- 设备状态监控
- 工艺参数调参与标定
- C++ / Qt / PySide / PyQt 的工业工作台

## 2. 信息架构

### 固定骨架

工业软件优先采用以下布局：

1. 菜单栏
2. 左侧导航或工位列表
3. 中央视图或结果区
4. 右侧参数与动作面板
5. 底部日志、统计、结果遥测区

### 页面职责

- 左侧负责切换，不负责深层参数编辑
- 中间负责图像、曲线、表格、状态卡等高价值信息
- 右侧负责输入、动作、导出、帮助提示
- 底部负责过程记录，不取代中间结果区

## 3. 主题系统

### 深色模式

适合值守与连续作业。

- 主背景建议落在深灰而非纯黑
- 高亮色集中用于动作按钮与状态选中
- 图像视图需要略深于整体背景，避免边界不清

### 浅色模式

适合调试、培训和截图。

- 主背景使用低对比浅灰，不直接上纯白
- 面板与输入区要保留层级差
- 状态文字在浅色环境下仍要有足够对比度

### 告警表达

告警至少由两层信号构成：

- 颜色
- 文本 / 图标 / 编号

不要依赖纯色块告诉用户“异常在哪里”。

## 4. 中央视图区设计

中间区域是工业视觉软件的核心，不允许被参数表单压缩成边角。

### 必备能力

- 滚轮缩放
- 拖拽平移
- 适应窗口
- 1:1 查看
- ROI 框选
- 对比图加载与清除
- ROI / 检测框叠加
- 结果文字区
- 图像区与结果区的可拖拽分割
- 页面层保存当前 ROI 状态，便于算法联动

### 常见扩展

- 多相机标签页
- 多图网格
- 历史图像回放
- 误检样本对比

## 5. 参数区设计

参数区应按“输入 -> 动作 -> 输出 -> 提示”排序。

推荐结构：

1. 输入路径与来源
2. 当前参数与开关
3. 主要动作按钮
4. 输出目录与导出按钮
5. 操作提示与风险提示

避免把动作按钮散落到页面各处。

## 6. 底部遥测区设计

推荐固定为 3 个标签页：

- 运行日志
- 统计摘要
- 最近结果

### 运行日志

保留完整过程，适合排查错误。

### 统计摘要

显示累计事件数、当前页面、当前主题、任务状态等摘要。

### 最近结果

展示最近几次输出，适合操作员快速回看，不必滚完整日志。

## 7. 菜单与全局动作

### 文件

- 打开项目
- 打开输出目录
- 导出运行日志
- 保存当前布局
- 加载布局快照
- 导出
- 退出

### 设置

- 深色 / 浅色主题
- 停靠面板显示控制
- 日志面板开关与清空
- 恢复默认布局
- 快捷键配置

### 说明

- 使用说明
- 版本信息
- 关于

菜单栏只收纳跨页面通用动作。

## 8. 线程与工程化

- UI 与算法层分离
- 图像处理任务不直接运行在主线程
- 页面只组织输入输出，不拥有底层算法状态
- 为长任务定义统一 worker 接口

如果界面出现卡顿，先检查是否把图像处理、文件扫描、批量统计放进了 UI 线程。

## 9. 设计流程

### 第一步：确定主骨架

先画出五层结构，不先做按钮细节。

### 第二步：确定主题令牌

先定背景、面板、边框、文字、强调色，不先写零散样式。

### 第三步：确定页面基类

把标题、状态卡、图像区、结果区、参数区抽成统一基类。

### 第四步：落单页

每个页面只填自己的输入、动作和结果摘要。

### 第五步：加验证

至少用 smoke test 约束：

- 页面数量
- 参数面板联动
- 菜单栏存在
- 主题切换可用
- 底部标签区存在

## 10. 常见误区

### 误区 1：把工业软件做成后台表单

结果是图像不够大，操作员只能不停翻参数。

### 误区 2：只有深色，没有浅色

值守舒服，但调试、培训、截图体验差。

### 误区 3：日志区承担一切

最后定位问题只能全文搜索，效率极低。

### 误区 4：每个页面随意排布

用户跨页学习成本高，培训与维护都变重。
