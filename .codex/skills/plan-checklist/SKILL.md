# 计划检查清单

把"口头讨论过的方向"固定成可执行文档，避免每次重新解释边界、优先级和已完成状态。

## 何时使用

- 用户说"重新梳理计划""给我总计划和分计划""生成可打钩文档"
- 准备新开 worktree，但需要先冻结范围和步骤
- 旧计划已经失真，需要基于最近对话重新整理

## 固定输出

至少输出 3 层文档：

1. **实施主计划** `docs/plans/YYYY-MM-DD-<slug>.md`
   - 目标、范围、任务阶段和验收

2. **总览入口** 总计划-打钩版.md
   - 保留项、排除项、阶段状态

3. **分计划** 子计划-打钩版.md（至少 2 份）
   - 一份给算法与数据流
   - 一份给 UI 与验收闭环

## 文档结构

### 总计划文档

- 背景
- 第一阶段目标
- 必保留
- 明确排除
- 相关文档
- 当前状态
- 验收标准

### 分计划文档

- 任务分组
- 每组下的 checkbox
- 当前状态
- 风险与注意事项

## 打钩规则

- 只把已经有证据的事项打成 `[x]`
- 文档创建本身可以打钩
- 未开始实现的代码任务保持 `[ ]`
- 状态变化时必须同时更新总计划和相关分计划

## 不要做的事

- 不要只写一份泛泛的长文
- 不要把旧计划整段复制过来不修状态
- 不要把"还没做的代码工作"提前打钩
