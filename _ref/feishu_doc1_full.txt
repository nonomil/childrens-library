六、核心架构：TEMPLATE_CONFIG 模板方案
6.1 设计原则
一个 CONFIG 对象控制全部内容，改 topic 就能换课题；引擎层永远不改。

const TEMPLATE_CONFIG = {
  topic: {
    title: "咕噜咕噜传动王国",
    emoji: "⚙️",
    sections: [ /* 所有页面/章节定义 */ ]
  }
}
// 引擎层：Canvas渲染器 / 游戏引擎 / 测验引擎 / 滚动动画 → 永不变

6.4 图片管线：images.status 字段方案（OpenClaw 补充）
在 TEMPLATE_CONFIG 中为每个 section 增加：

"images": {
  "status": "pending" | "generating" | "ready" | "failed",
  "fallback": "/assets/fallback-placeholder.png"
}
模板层自动感知：pending 显示 loading 骨架；ready 才渲染图片。把 Gemini 配图 cron 的状态拉进模板运行时，而非靠外部脚本手动补。

七、组件生命周期契约（最高优先级待办）

// 每个组件必须实现以下接口：
function ComponentXxx(el, config) {
  return {
    mount()   { /* 挂载到 DOM，启动动画/事件 */ },
    unmount() { /* 清理 RAF / 事件监听 / Canvas context */ },
    resize()  { /* 响应窗口变化，重绘 Canvas */ },
    update(newConfig) { /* 热更新配置（如切换主题时调用）*/ }
  }
}
重要性：没有 mount/unmount/resize 契约，换主题时组件行为不可预测。这是 TEMPLATE_CONFIG 从「静态配置」变成「可复用模板引擎」的关键缺失。
