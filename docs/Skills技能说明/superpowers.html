Superpowers

What is Superpowers

Superpowers 不是一个普通 skill，也不应该用“安装单个 skill”的思路来理解。 它更像一套给 AI 编程工具用的工程化开发框架：把需求澄清、计划拆解、测试驱动开发、 子智能体执行、代码审查和完成前验证串成一套完整工作流。

Overview

Why it matters

Why it matters

很多人把 AI 当成“直接写代码”的工具，但真正复杂的项目并不是少了几行代码，而是少了结构化流程。 Superpowers 的价值就在这里：它让 AI 先想清楚，再动手；先写计划，再执行；先验证，再宣称完成。

What problems it solves

它主要解决三类问题：需求不清就开始写、上下文越来越乱导致质量下降、任务完成了却缺少验证。 对复杂功能、多人协作和持续迭代项目尤其有帮助。

Architecture

Layered architecture

Layered architecture

从你提供的攻略看，Superpowers 采用分层结构：用户层负责接入不同 AI 编程工具，框架层负责自动注入技能上下文， 执行层负责子智能体调度，输出层则把设计、代码、测试等结果统一落到 Git 管理中。

Skills are the core abstraction

它的核心抽象是 skills。每个 skill 都描述一种任务场景和执行流程，所以它更像“流程模板系统”， 而不是简单的命令别名集合。

Execution

Subagent-Driven Development

Subagent-Driven Development

这是 Superpowers 里很关键的思路。它让每个任务尽量交给全新上下文的子智能体去做，避免长会话上下文越来越乱。 配合两阶段审查，能把“实现正确”和“代码质量好”分开检查。

Two-phase review

第一阶段看规范是否满足，第二阶段看代码质量是否达标。这样不会因为“代码看起来挺整齐”就忽略需求缺漏， 也不会因为风格争论掩盖功能问题。

Workflow

Common workflow and core skills

brainstorming

先澄清需求，再形成设计方案，避免一上来就写代码。

writing-plans

把复杂任务拆成可以执行和验证的小步骤，适合作为开发前置阶段。

test-driven-development

要求先写失败测试，再写最小实现，适合功能开发和 bug 修复。

subagent-driven-development

把明确任务交给新的子智能体执行，并通过审查循环快速迭代。

verification-before-completion

在声称“完成”之前强制做 fresh verification，避免只靠感觉交付。

using-git-worktrees

适合需要隔离工作区、并行尝试多个实现方向时使用。

Install

Correct install routes

Claude Code plugin route

如果你是在 Claude Code 里使用 Superpowers，按你给的攻略，正确路线是先加 marketplace，再安装插件。 这才是适合 Claude Code 的主路径，不是用 `skill-installer` 去装它。

Claude Code 
/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

Codex local bootstrap route

如果你是在当前这套本地 Codex 环境里使用 Superpowers，这个项目保留的是 clone + bootstrap 路线， 更贴近当前 Windows 工作流。

Codex Local 
node C:/Users/Administrator/.codex/superpowers/.codex/superpowers-codex bootstrap
