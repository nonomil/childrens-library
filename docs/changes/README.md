# docs/changes/ — 变更记录

> 给**人看**的 changelog。团队成员快速了解"改了什么、影响什么、能不能升级"。

## 目录用途

存放每次代码变更的发布说明（Release Note 风格），按时间倒序排列。

## 文档格式

### 主文档：`CHANGELOG.md`

按版本/里程碑归组的变更摘要，每条一行 + 链接到分文档。

### 分文档：`序号-日期-hash-标题.md`

示例：`0042-2026-04-02-abc1234-user-auth.md`

每份分文档包含：
- **日期 / 类型 / 影响范围**
- **新增了什么**：一句话说明
- **升级注意**（Breaking Changes）：需要改什么配置、加什么依赖
- **验证方法**：怎么确认改动生效

## 生成时机

review 通过 + git 提交成功后，自动生成分文档并追加到 CHANGELOG.md。

## 双轨配套

同一改动会在 `.claude/memory/context/` 生成 AI 看版（聚焦决策理由和注意事项），与本目录同名。
