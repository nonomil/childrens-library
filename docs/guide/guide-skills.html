技能是什么？

技能（Skill）是一个 Markdown 文件，描述了 AI 在特定场景下应该怎么做。它相当于给 AI 装上了一个"专业能力包"——有了 UI 设计技能，AI 就知道怎么做漂亮的界面；有了 Debug 技能，AI 就知道先写回归测试再修复。

技能文件格式：YAML frontmatter（name + description）+ Markdown正文
触发方式：用户说匹配的关键词，AI 自动加载对应技能
存放位置：.claude/skills/（Claude Code 侧）.codex/skills/（Codex 侧）

为什么需要自制技能？

"最牛逼的 Skill，永远是下一个，你自己造的那个。" —— 通用的 Skill 解决通用问题，但只有你自己知道你的工作流里哪个环节最痛、最值得自动化。

四种技能制作方法

1 样板法

拿最满意的交付物当模板，让 AI 提炼标准封装成 Skill。

适合：你已经有做得很好的产出物（报告、方案、代码）

2 流程法

把固定工作步骤的输入输出写清楚，串成自动化 Skill。

适合：每天重复的工作流程（日报、部署、检查）

3 归纳法

回看聊天记录，找出反复让 AI 做的事，补成 Skill。

适合：发现某些指令你每周都要重复输入

4 经验法

把脑子里"只可意会"的隐性知识写成文档绑进 Skill。

适合：你有丰富的行业经验，但每次都要从头跟 AI 解释

共同点：都是从已有经验出发。你做过的事、踩过的坑、积累的模板，有了才能提炼。

Skill-Creator 教程

Skill-Creator 是 Anthropic 官方提供的技能生成工具。你只需描述想要的场景，它会自动分析需求、生成完整的 SKILL.md + references/ 目录。长期来看，这是把个人经验转化为 AI 能力的最高效路径。

核心工作流

1
描述场景：用一句话说明你想要什么技能（如"帮我画高颜值流程图"）
2
深度思考：AI 在动手前先写"草稿"——骨架、逻辑、图表类型，逼迫自己先想清楚
3
生成技能：输出 skill.md + references/ 目录（颜色规范、布局规则等）
4
Evals 测试：自动 A/B 对比（开 Skill vs 不开），量化验证效果
5
迭代打磨：生成→比对→找茬→修改，反复微调直到稳定

痛点拆解

基础模型不是"做不到"，而是做得不够稳定、不够一致。Skill 的价值是"定向增强"，而非"从零创造"。

颜色体系

固定流程

加"深度思考"前置步骤 + 收敛图表类型为 6 类：workflow / architecture / comparison / swimlane / venn / chart。

文件结构

skill.md（主控）+ references/color-palette.md（视觉标准）+ references/pattern-library.md（布局规则）。

核心洞察："模型只是执行者，真正决定上限的，是你自己对细节的理解。什么样的箭头更合适、什么颜色更克制、什么间距更舒服——这些判断，AI 不会凭空替你建立。"

Superpowers 技能体系

Superpowers 是一个面向 AI 编程的工程化开发插件，提供 20+ 个可组合 Skills，覆盖需求梳理到代码审查的完整流程。

标准开发工作流

1
Brainstorming：通过问答澄清需求 → 分块展示设计方案 → 人工确认
2
Git Worktree：创建独立的 Git 工作树，隔离开发环境
3

4

5
TDD：RED → GREEN → REFACTOR 循环
6
Code Review：最终质量检查
7
Finish Branch：合并完成

Superpowers

What is Superpowers

Superpowers 不是一个普通 skill，也不应该用"安装单个 skill"的思路来理解。它更像一套给 AI 编程工具用的工程化开发框架：把需求澄清、计划拆解、测试驱动开发、子智能体执行、代码审查和完成前验证串成一套完整工作流。

Why it matters + What problems it solves

Why it matters

很多人把 AI 当成"直接写代码"的工具，但真正复杂的项目并不是少了几行代码，而是少了结构化流程。Superpowers 的价值就在这里：它让 AI 先想清楚，再动手；先写计划，再执行；先验证，再宣称完成。

What problems it solves

它主要解决三类问题：需求不清就开始写、上下文越来越乱导致质量下降、任务完成了却缺少验证。对复杂功能、多人协作和持续迭代项目尤其有帮助。

Layered architecture

Superpowers 采用分层结构：用户层负责接入不同 AI 编程工具，框架层负责自动注入技能上下文，执行层负责子智能体调度，输出层则把设计、代码、测试等结果统一落到 Git 管理中。

1
用户层：负责接入不同 AI 编程工具，接收你的自然语言需求。
↓
2
框架层：负责自动注入技能上下文、组织规划与验证流程。
↓
3
技能层：skills 是核心抽象。每个 skill 都描述一种任务场景和执行流程，所以它更像"流程模板系统"，而不是简单的命令别名集合。

Subagent-Driven Development

Subagent-Driven Development

这是 Superpowers 里很关键的思路。它让每个任务尽量交给全新上下文的子智能体去做，避免长会话上下文越来越乱。配合两阶段审查，能把"实现正确"和"代码质量好"分开检查。

Two-phase review

第一阶段看规范是否满足，第二阶段看代码质量是否达标。这样不会因为"代码看起来挺整齐"就忽略需求缺漏，也不会因为风格争论掩盖功能问题。

Common workflow and core skills

brainstorming

先澄清需求，再形成设计方案，避免一上来就写代码。

writing-plans

把复杂任务拆成可以执行和验证的小步骤，适合作为开发前置阶段。

test-driven-development

要求先写失败测试，再写最小实现，适合功能开发和 bug 修复。

subagent-driven-development

把明确任务交给新的子智能体执行，并通过审查循环快速迭代。

verification-before-completion

在声称"完成"之前强制做 fresh verification，避免只靠感觉交付。

using-git-worktrees

适合需要隔离工作区、并行尝试多个实现方向时使用。

Skill-Creator 详细教程

Skill-Creator workflow

最直接的用法就是把你要解决的场景、输入、输出和检查清单说清楚，让它直接生成完整 SKILL.md 初稿。

Describe what you need 
请使用 skill-creator，帮我生成一个用于[场景]的自定义 skill。
我会提供目标、输入、输出和检查清单，
你直接生成完整 SKILL.md 初稿。

career.skill method

按职业拆是最不容易遗漏的方式——每个职业都有固定的工作流、反复出现的输出物、永远踩不完的坑。

用法：在 Claude Code 里说 我是 [职业]，帮我拆 Skill，它会输出 5-8 个核心工作流 Skill 的制作指南。

career.skill 
我是 [职业]，帮我拆 Skill
