# 128课件差异修复方案 — 融合 AutoResearchClaw 方法论

> 创建时间：2026-05-29
> 方法论来源：AutoResearchClaw (UNC + Meta + Google, 2026)
> 目标：修复128课件与5份规范文档之间的差异，提升体验一致性

---

## 一、方法论映射：AutoResearchClaw → 课件项目

| AutoResearchClaw 原则 | 课件项目应用 |
|----------------------|-------------|
| **23阶段管道 + 检查点** | 每个修复任务分 需求→实现→自验→集成 四阶段，每阶段有明确交付物 |
| **多智能体辩论** | 修复方案不唯一时，列 A/B/C 方案 + 优劣对比，用户决策 |
| **自愈执行** | 修改后自动跑 test_all.py 验证，失败则诊断→修复→重试（最多3轮） |
| **Pivot/Refine/Proceed** | 每个任务完成后：Proceed(继续) / Refine(需优化) / Pivot(方向错，重来) |
| **验证注册表** | 所有数字（文件数、通过率、图片数）必须来自 test_all.py 实际输出 |
| **少而准的人类介入** | 6个高杠杆决策点让用户确认，其余自动执行 |
| **跨运行经验库** | 记录到 `.claude/memory/lessons/`，避免重复踩坑 |

## 三、差异分类与修复方案

### 3.1 P0 — 核心体验缺失（阻塞发布）

#### 3.1.1 Steve 精灵图动画
- **现状**：emoji 🧑 代替，无行走动画，无像素风沉浸感
- **规范**：32×32 像素精灵图，4帧行走动画
- **方案A**（推荐）：CSS sprite + 4帧动画，用纯CSS绘制像素Steve（无外部图片依赖）
- **方案B**：用 canvas 绘制像素角色
- **方案C**：保持emoji但添加GSAP动画（最低成本）
- **验收**：Steve 有行走动画，方向可切换，点击触发说话

#### 3.1.2 3个占位故事（space-d2/d3/d4）
- **现状**：只有emoji占位，无实际内容
- **方案**：AI生成简短故事内容（8-10页，中英双语），保持太空冒险主题
- **范围裁剪**：不提供删除选项（违反项目协作规范，且破坏故事屋完整性）
- **验收**：每个故事文件有≥8页实际内容，翻页正常，最后一页有celebrate()

### 3.2 P1 — 规范偏差（影响一致性）

#### 3.2.1 CSS主题变量系统
- **现状**：128个文件各自硬编码颜色，无data-type驱动的主题
- **规范要求**：
  - `nursery`: `--bg: #FFF9E6` 暖黄，高饱和水彩风
  - `story`: `--bg: #FFF8F0` 暖白，温馨渐变
  - `science`: `--bg: #F0F8FF` 蓝白，信息感
  - `courseware`: `--bg: #FAFAFA` 纯白，干净
- **方案**：在 shared/courseware.css 中按 `[data-type]` 选择器定义CSS变量
- **验收**：4种data-type各有对应主题色，切换data-type属性可看到颜色变化

#### 3.2.2 解锁逻辑修正
- **现状**：数学解锁条件 `unlockRequirement: 3` 检查的是所有zone总完成数
- **规范**：数学集市 = 完成3课**英语**，科学实验室 = 完成5课**任意**
- **方案**：修改 `isZoneUnlocked()` 函数，支持检查特定zone完成数
- **验收**：数学需英语≥3才解锁，科学需总完成≥5

#### 3.2.3 宠物系统对齐
- **现状**：6种宠物，直接选择，固定成长值，无蛋孵化/偏好食物
- **规范**：4种宠物(猫/狗/鹦鹉/狐狸)，蛋+药水孵化，偏好食物+5/普通+2
- **简化方案**（推荐）：保留6种宠物（比规范多2种，体验更好），但增加偏好食物机制
- **验收**：每种宠物有偏好食物标记，喂偏好食物成长值更高

### 3.3 P2 — 体验提升（锦上添花）

#### 3.3.1 像素风进度条
- **现状**：圆角渐变进度条
- **规范**：像素风分段条
- **方案**：CSS实现分段像素进度条，用 `image-rendering: pixelated`
- **验收**：进度条有明显的分段感，与村庄像素风格一致

#### 3.3.2 金币浮动动画
- **现状**：village-reporter只显示金币数字
- **方案**：完成时显示 `+N 金币` 浮动上升动画
- **验收**：完成课件后有金色 `+5` 从底部浮起消失

#### 3.3.3 404图片onerror降级
- **现状**：部分文件图片缺少onerror处理
- **方案**：所有 `<img>` 标签添加 `onerror="this.src='data:image/svg+xml,...';this.onerror=null"`
- **验收**：所有图片标签有onerror处理

## 四、执行管道（4阶段 × 每任务）

```
需求确认 → 实现 → 自验(test_all.py) → 集成验收
   (G1)      ↓         ↓ 失败→自愈(≤3轮)     (G6)
            编码      通过→下一任务
```

### 自愈机制
```
修改代码 → 运行 test_all.py
  ↓ 通过 → Proceed（继续下一任务）
  ↓ 失败 → 读取错误输出 → 诊断原因 → 修复 → 重试
  ↓ 连续失败3次 → Pivot（换方案）或报告用户
```

## 五、验证注册表（数字必须有出处）

| 指标 | 验证方式 | 当前值 | 目标值 |
|------|---------|--------|--------|
| 总文件数 | `python test_all.py` 输出 | 128 | 128 |
| 测试通过率 | `python test_all.py` 输出 | 128/128 | 128/128 |

## 七、本轮范围裁剪声明

以下功能经评估后**明确排除在本轮之外**，记录裁剪理由和风险接受：

| 功能 | 裁剪理由 | 风险接受 | 下轮入口条件 |
|------|---------|---------|-------------|
| Turn.js 翻书效果 | 当前自定义JS翻页已可用，替换成本高（128文件） | 用户体验略降 | 用户明确要求或有自动化迁移工具 |
| Edge-TTS 预生成音频 | Web Speech API 已满足基本需求，mp3需存储方案 | 音质一般 | 课程数>30或用户反馈音质问题 |
| Ink/inkjs 分支故事 | 需引入新引擎+重写故事结构，工作量>2周 | 故事线性 | 用户明确要求分支叙事 |
| 账号云同步 | 需后端服务，当前localStorage足够家庭使用 | 单设备 | 多设备需求出现 |
| 宠物蛋掉落机制 | 纯装饰功能，不影响核心体验 | 无 | 宠物系统稳定后 |
| expToLevel 经验公式 | 当前固定金币值对6岁儿童更友好（简单可预期） | 无长期激励 | 用户反馈缺少成长感 |
| Steve 固定位置/Alex门口行为 | 当前随机走动更有探索感，固定位置需额外状态管理 | 角色定位偏差 | 用户明确要求 |

**裁剪原则**：优先保证128文件一致性 > 新功能 > 体验打磨
