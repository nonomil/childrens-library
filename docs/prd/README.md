# docs/prd/ — 产品需求文档

> 产品/功能级别的需求文档，连接"用户要什么"和"代码怎么写"。

## 目录用途

- 存放项目级和功能级的产品需求文档（PRD）
- `goals.md`：项目整体目标与背景上下文
- `[feature]-prd.md`：按功能拆分的需求文档

## 文档格式

### goals.md

项目级文档，回答：
- 项目解决什么问题？
- 目标用户是谁？
- 核心价值是什么？
- 成功标准是什么？

### [feature]-prd.md

功能级文档，包含：
- **背景**：为什么需要这个功能
- **目标**：要达成什么（可量化）
- **用户故事**：作为 [角色]，我想 [操作]，以便 [价值]
- **验收标准**：可测试的通过条件
- **技术假设**：依赖的前置条件
- **范围边界**：明确不包括什么

## 生成时机

- `goals.md`：项目初始化时或 CLAUDE.md 门禁需求讨论后生成
- `[feature]-prd.md`：用户说"新功能 PRD"时，AI 智能引导补充关键信息后生成

## 工作流映射

```
用户说"新功能 PRD" → AI 判断输入是否明确
  → 不明确：引导补充（目标/用户/验收标准）
  → 明确：直接生成 docs/prd/[feature]-prd.md
  → 自动触发 plan skill 拆解任务
```
