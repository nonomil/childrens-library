## 二、核心发现：按内容类型分类（非主题分类）

### 2.1 为什么不能一套主题通吃

现有文档提出"太空冒险/森林动物/海洋世界/童话城堡"四个视觉主题。经搜索验证，**行业最佳实践是按内容类型区分视觉风格**，而非按场景主题：

- 童谣的核心是**节奏感**，视觉要服务于韵律
- 故事的核心是**情感共鸣**，视觉要随情绪变化
- 科普的核心是**信息层级**，视觉要引导探索
- 课件的核心是**学习路径**，视觉要清晰结构化

一套"太空蓝"或"森林绿"的配色无法同时满足这四种需求。

### 2.2 四大内容类型定义

| 类型 | 对应现有内容 | 核心目标 | 年龄段 |
|------|------------|---------|--------|
| **童谣/儿歌** | 古诗、韵文、儿歌类 | 韵律感知 | 0-4岁 |
| **绘本故事** | 中文故事、英语故事、睡前故事 | 情感共鸣 | 3-8岁 |
| **科普互动** | 齿轮传动、太阳系、恐龙、水循环 | 知识探索 | 4-8岁 |
| **课件教材** | 数学、英语语法、识字练习 | 技能习得 | 5-8岁 |

### 2.3 四类视觉风格对比

| 维度 | 童谣/儿歌 | 绘本故事 | 科普互动 | 课件教材 |
|------|----------|---------|---------|---------|
| **插画风格** | 水彩/剪纸/民间风 | 多样，情感驱动 | 写实插画+信息图 | 扁平/极简 |
| **色彩策略** | 高饱和、明快 | 随情绪暖冷变化 | 功能分区色块 | 系统化一致配色 |
| **图文比** | 6:4（图为主） | 7:3~8:2 | 7:3（图+标注） | 5:5 |
| **文字角色** | 主角（可唱） | 叙事者 | 标注者 | 指导者 |
| **翻页逻辑** | 节奏重复 | 悬念/转折 | 知识递进 | 步骤推进 |
| **交互核心** | 跟唱/拍打/点读 | 翻页/场景探索/角色对话 | 点击揭示/拖拽实验/模拟 | 练习/反馈/进度条 |
| **情绪基调** | 欢快/温馨 | 随剧情变化 | 好奇/惊奇 | 稳定/鼓励 |

## 四、每种内容类型的模板方案

### 4.1 童谣/儿歌模板

**设计要点**（来自行业研究）：
- 文字本身是视觉元素，大字号+韵律分行
- 版式呼应重复句式（叠句用相同视觉处理）
- 插画简洁，元素不宜过多
- 交互核心：**跟唱、点读、节奏拍打**

**页面结构**：
```
┌──────────────────────────┐
│    [韵律配图 - 剪纸风]    │
│                          │
│   🎵 小星星，亮晶晶~     │  ← 大字号，押韵字高亮
│      满天都是小星星~      │
│                          │
│  ┌──────┐  ┌──────┐     │
│  │  ▶️  │  │    │     │  ← 播放/跟唱/再读一遍
│  └──────┘  └──────┘     │
│                          │
│  [节奏动画：星星随节拍闪烁] │
└──────────────────────────┘
```

**CONFIG示例**：
```json
{
  "type": "nursery",
  "title": "小星星",
  "targetAge": [2, 4],
  "audioSync": true,
  "pages": [
    {
      "text": "一闪一闪亮晶晶",
      "highlightRhyme": ["星", "晶"],
      "audio": "nursery-star-1.mp3",
      "animation": "star-twinkle-beat",
      "beat": [0, 0.5, 1.0, 1.5]
    }
  ]
}
```

**配图Prompt**：
```
Chinese paper-cut style illustration, traditional folk art,
bright red and gold colors, simple bold shapes,
cute stars and moon, children's nursery rhyme,
no text, festive warm feeling
```

### 4.2 绘本故事模板

**设计要点**：
- 翻页处设计悬念/转折（最关键的叙事工具）
- 色彩随叙事情绪变化（温馨暖色调→紧张冷色调→结尾暖色）
- 角色对话用气泡样式，旁白用正文样式
- 交互核心：**翻页推进、角色对话点击、场景探索**

**页面结构**：
```

│  │   [故事配图]       │  │  ← 配图占60-70%

│                          │
│  Steve走进了教室...      │  ← 旁白文字
│                          │
│  ┌────────────────┐      │
│  │ "你好！我是Alex"│      │  ← 角色对话气泡（可点击播放语音）

│                          │
```

### 4.3 科普互动模板

**设计要点**（参考《第一次发现》《神奇校车》DK系列）：

- 单页信息量不能过大，通过视觉层级分解

## 五、有声绘本方案（基于现有调研迭代）

> 来源：完整合并版调研报告§2.5 TTS方案对比 + §五 家庭教育AI设计原则

### 5.1 TTS方案选择（维持现有结论）

| 方案 | 用途 | 成本 | 推荐 |
|------|------|------|------|
| Edge-TTS | 默认方案，构建阶段生成mp3 | 免费 | ✅ 首选 |
| Qwen3-TTS-VC | 高级方案，家长声音克隆 | 免费（自部署） | 未来升级 |
| Web Speech API | 兜底方案（浏览器端） | 免费 | 不推荐（音质差） |

### 5.2 角色音色分配（维持现有方案）

| 角色 | Edge-TTS音色 | 说明 |
|------|-------------|------|
| 旁白 | zh-CN-XiaoxiaoNeural | 晓晓，温柔女声，最适合儿童 |
| Steve | zh-CN-YunxiNeural | 云希，男童声 |
| Alex | zh-CN-XiaoyiNeural | 晓伊，女童声 |
| Bob | zh-CN-YunyangNeural | 云扬，长辈声 |

### 5.3 音频交互设计（来自全景指南§四.1）

- 默认自动朗读每页文本
- 支持"再读一遍"按钮（孩子常要求重复）
- 翻页声、选择正确提示音、环境音（可选）
- 3分钟原则：单次互动不超过3分钟，超时自动暂停+鼓励休息

### 5.4 音频存储策略（维持现有结论）

- 起步：音频放GitHub仓库（<10个课件）
- 超过10个课件后迁移到阿里云OSS/腾讯云COS

## 七、分支叙事方案（维持现有方案）

> 来源：完整合并版调研报告§2.2 + §六.2

### 7.1 技术选型：Ink/inkjs（不变）

- MIT授权，AI生成脚本最友好
- 纯文本脚本 → Claude/DeepSeek可批量生成.ink文件
- inkjs在浏览器端运行，无需后端

### 7.2 选择设计原则（不变）

- 没有错误答案，每个选择都导向正面结局
- 选择有实际影响，不是假分支
- 分支后可回退，鼓励重玩
- 90%安全选择 + 10%需要勇气的选择

## 八、内容更换机制

### 8.1 三种更换方式

| 方式 | 适合谁 | 操作 |
|------|--------|------|
| 改JSON配置 | 非开发者 | 编辑 content/[绘本id]/config.json → 刷新生效 |
| Markdown→CONFIG | 批量生产 | 写Markdown → `md-to-config.py` → 自动生成JSON |
| AI生成 | 最高效 | 输入主题+类型+年龄 → AI生成CONFIG → 审核 → 部署 |

### 8.2 新绘本上线流程

```
步骤1：确定内容类型（5分钟）
    童谣/绘本故事/科普互动/课件教材 → 决定视觉风格+交互模式

步骤2：AI生成内容（15分钟）
    用对应类型的Prompt模板 → 生成CONFIG JSON + 故事文本

步骤3：AI生成配图（20分钟）
    用对应类型的配图Prompt → 批量出图

步骤4：TTS生成音频（10分钟）
    Edge-TTS → 批量生成mp3

步骤5：组装测试（20分钟）
    CONFIG + 配图 + 音频 → 本地预览 → 调整

步骤6：审核上线（10分钟）
    内容安全检查 → 推送GitHub → 自动部署
```
