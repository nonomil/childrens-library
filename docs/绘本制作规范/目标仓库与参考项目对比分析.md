### 1.4 共享工具库分析（courseware.js，133行）

| 函数 | 功能 | 实现方式 |

| `stopSpeaking()` | 停止播放 | `audio.pause()` + `speechSynthesis.cancel()` |

| `initKeyboard()` | 键盘导航 | `ArrowLeft/Right` |

## 二、现有架构的优势与问题

### 2.1 优势（不要丢掉的）

| 优势 | 说明 |
|------|------|
| **零依赖** | 纯前端，打开即用，无需服务器 |
| **一页一课** | 每个HTML独立，坏一个不影响其他 |
| **离线可玩** | 本地文件直接打开浏览器就能用 |
| **触摸优先** | 专为平板设计，大按钮（48px+） |
| **双层语音** | MP3优先→TTS降级，覆盖率100% |
| **生成流水线** | Python脚本批量生成，已有成熟模板 |
| **学科配色** | 已按学科区分颜色（绿/红/蓝/橙） |
| **角色一致** | Steve/Alex/Bob贯穿所有课件 |
| **互动丰富** | 拖拽、拼词、配对、测验、庆祝动画 |
| **方法论文档** | COURSEWARE-METHODOLOGY.md 已有完整规范 |

### 2.2 问题（需要优化的）

| # | 问题 | 影响 | 严重度 |
|---|------|------|--------|
| 1 | **CSS/JS大量重复** | 每个HTML内联~300行相同样式，维护改一处要改111处 | 高 |
| 2 | **无CONFIG驱动** | 换内容=改HTML代码，非开发者无法操作 | 高 |
| 3 | **共享库太薄** | 133行JS+32行CSS，大量逻辑在各HTML中重复 | 高 |
| 4 | **童谣风格与课件不区分** | 童谣用Fredoka One字体+暖橙色，课件用Nunito+学科色，但没有系统化 | 中 |
| 5 | **无分支叙事** | 所有课件是线性的，没有"孩子做选择→故事变化" | 中 |
| 6 | **无组件生命周期** | Canvas组件（齿轮）没有mount/unmount，可能内存泄漏 | 中 |
| 7 | **音频管理分散** | 每个HTML自己管理Audio对象，无统一音频队列 | 中 |
| 8 | **图片无预加载** | 翻页时才加载图片，可能有白屏闪烁 | 低 |
| 9 | **无首页索引** | `courseware/index.html`不存在，只有MkDocs文档 | 低 |

## 三、参考项目分析

### 3.1 Howler.js（24k⭐，音频管理）

**核心能力**：
- 跨浏览器音频播放（Web Audio API + HTML5 Audio降级）
- 自动检测格式支持（mp3/ogg/wav/webm）
- 音频精灵（sprites）：一个文件多段播放
- 空间音频、淡入淡出、速率控制
- 零依赖，5KB gzip

**对本项目的价值**：
- 替换现有的 `new Audio(src)` 方式
- 统一音频队列管理（避免多音频同时播放）
- 音频精灵可减少HTTP请求（多个短音效合并为一个文件）

**是否引入**：可选。当前 `new Audio()` + Web Speech API 方案已够用，但如果有10+课件需要同时播放多段音频（如背景音乐+朗读+音效），Howler.js会更稳定。

### 3.2 StPageFlip（788⭐，翻页库）

**核心能力**：
- TypeScript编写，零依赖
- Canvas和CSS3D双渲染模式
- 支持移动端触摸、响应式
- 自定义页面尺寸

**对本项目的价值**：
- 当前项目不用翻页效果（每个HTML是单页+内部导航）
- 如果要做"绘本故事"类型（逐页翻书体验），可以考虑

**是否引入**：暂不需要。当前"一页一课"的模式更适合5-7岁幼儿，翻页书模式更适合纯故事阅读。

### 3.3 inkjs（1.8k⭐，分支叙事引擎）

**核心能力**：
- Ink脚本语言的JavaScript运行时
- 支持分支选择、变量、条件逻辑
- MIT授权，纯前端

**对本项目的价值**：
- 让课件有"选择→不同结局"的能力
- AI可批量生成.ink脚本
- 适合英语故事、品格教育类课件

**是否引入**：推荐。作为"分支故事"组件类型加入，不替换现有线性课件。

## 四、优化建议（基于实际代码）

### 4.1 第一步：提取公共样式和组件（高优先级）

**问题**：每个HTML内联~300行相同样式，111个文件=33,000行重复CSS。

**方案**：从现有HTML中提取高频CSS到 `shared/courseware.css`，不改变渲染效果。

/* 需新增： */

.page { display: none; padding: 32px 24px 100px; min-height: 480px; }

/* 按钮系统 */

/* 词汇卡 */

### 4.3 第三步：按内容类型区分视觉风格（中优先级）

**现状**：已有学科配色（英语绿/中文红/数学蓝/童谣橙），但只是主色不同，布局和交互模式没有区分。

**方案**：在现有学科色基础上，增加内容类型维度：

| 类型 | 现有配色 | 建议增强 |
|------|---------|---------|
| 童谣/儿歌 | 橙 #FF9800 | 字体Fredoka One ✓，增加节奏动画、歌词逐行高亮 |

### 4.4 第四步：音频管理统一（中优先级）

**问题**：每个HTML自己 `new Audio()` 管理播放，111个文件各写各的。

**方案**：扩展 `courseware.js`，增加音频队列：

```javascript
// 在现有 courseware.js 基础上扩展
window.audioQueue = {
  current: null,
  queue: [],
  
  play(src, text, onEnd) {
    this.stop();
    var a = new Audio(src);
    a.onerror = function() { speakTTS(text); if(onEnd) onEnd(); };
    a.onended = function() { if(onEnd) onEnd(); };
    a.play().catch(function(){ speakTTS(text); if(onEnd) onEnd(); });
    this.current = a;
  },
  
  stop() {
    if (this.current) { this.current.pause(); this.current = null; }
    if (window.speechSynthesis) window.speechSynthesis.cancel();
  },
  
  // 依次播放多段音频
  playSequence(items) {
    var i = 0;
    var self = this;
    function next() {
      if (i >= items.length) return;
      self.play(items[i].src, items[i].text, function() { i++; next(); });
    }
    next();
  }
};
```

### 4.5 第五步：分支叙事组件（低优先级，新增能力）

**方案**：在现有课件体系中增加 `branch-story` 组件类型，用 inkjs 驱动。

**不改现有111个HTML**，新增：
- `shared/inkjs.min.js`（inkjs运行时）
- `shared/branch-story.js`（组件，~200行）
- `stories/*.ink`（Ink脚本文件）

## 五、不需要做的事（避免过度工程化）

| 不做 | 原因 |
|------|------|
| 换翻页引擎 | "一页一课"模式更适合5-7岁，Turn.js/StPageFlip用不上 |

| 换TTS方案 | Web Speech API + MP3降级已跑通，Edge-TTS只在构建阶段用 |
| 建CONFIG体系推翻重来 | 从现有HTML提取数据即可，不需要重新设计CONFIG结构 |
