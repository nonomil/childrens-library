# 我的世界风格优化 — 合并需求文档

> 来源整合：`docs/我的世界风格优化建议/` (4份文档) + `docs/需求/账号管理+宠物系统.md`
>
> 项目：nonomil/childrens-library（儿童互动课件库）
>
> 目标用户：6岁，我的世界玩家，平板使用
>
> 核心问题：115+ 课件内容够，但孩子没有进入感、没有持续动力

---

## 一、根本诊断

现状是"超市货架"——115+ 课件平铺在那里，孩子不知道从哪开始，没有沉浸感。

**改造目标**：把课件库变成一个**可以成长的我的世界村庄**。
- 不碰现有课件内容，改造的是**包裹课件的"世界壳"**
- 每次打开都在同一个世界，有连续感
- 每个操作都有即时反馈（音效、动画、成长变化）
- 进度是可见的（建筑在那里，不会消失）
- 有意外发现（宝箱、隐藏区域）

---

## 二、需求分层总览

| 层级 | 需求 | 优先级 | 周期 | 依赖 |
|------|------|--------|------|------|
| **入口层** | 村庄地图首页 | P0 | 3-5天 | 无 |
| **进度层** | 成就 + 存档系统 | P0 | 4-6天 | 入口层 |
| **经济层** | 金币系统 + 每日任务 | P1 | 3-4天 | 进度层 |
| **情感层** | 宠物养成系统 | P1 | 1周 | 经济层 |
| **同步层** | 账号系统（多设备） | P2 | 1-2周 | 上述全部 |
| **叙事层** | 分支冒险故事 | P3 | 2周 | 入口层 |

## 三、入口层：村庄地图首页（Phase 1）

> 参考：`doc01_village.md`（详细设计）

### 3.1 核心设计

- 用一个**我的世界风格的村庄地图**替换现有的课件列表页
- 每个学科对应村庄里的一栋建筑，孩子点击建筑进入该学科课件
- **不碰任何现有课件**，一个新 HTML 文件搞定

### 3.2 建筑与学科映射

| 建筑 | 学科 | 角色 | 解锁条件 |
|------|------|------|---------|
| 英语学校 🏫 | 英语课件 | Steve 站在门口 | 默认解锁 |
| 中文图书馆 📚 | 语文/绘本 | Bob 爷爷 | 默认解锁 |
| 数学集市 🔢 | 数学 | — | 完成3课英语解锁 |
| 音乐广场 🎵 | 童谣 | Alex | 默认解锁 |
| STEM实验室 🔬 | 科学/齿轮 | — | 完成5课解锁 |

### 3.3 页面结构

```
village.html
├── header：村庄名 + Steve头像 + 今日星星数
├── main.village-map
│   ├── canvas#village-bg（像素风背景：草地、天空、云）
│   └── .buildings（5个建筑，绝对定位）
├── .village-characters（Steve 走动角色 + Alex）
└── .zone-panel（点击建筑后弹出的课件列表面板）
```

### 3.4 视觉规范

- **像素风**：`image-rendering: pixelated`，方块堆叠感
- **配色**：天空蓝 `#87CEEB`、草地绿 `#5D8A3C`、泥土棕 `#8B6914`、石砖灰 `#888`
- **字体**：标题 `Press Start 2P`（像素风），正文 `Nunito`（孩子可读性优先）
- **UI 面板**：半透明黑底 `rgba(0,0,0,0.75)`，金色高亮 `#FFD700`
- **进度条**：像素风分段条，非圆角渐变

### 3.5 Steve 角色动画

- 32×32 像素精灵图，4帧走路动画
- 在地图上巡逻走动，碰到边界转向
- 点击 Steve：弹语音气泡 + TTS 朗读一句话
- 固定台词："今天想去哪里学习？""我们去图书馆吧！""数学集市有好吃的！"

### 3.6 文件清单

```
新建：
├── village.html               ← 主入口
├── courseware/shared/village.js    ← 村庄状态管理
├── courseware/shared/village.css   ← 村庄样式
└── courseware/images/
    ├── steve-walk.webp        ← Steve精灵图（可用emoji/CSS占位）
    └── building-*.webp        ← 5个建筑图（可用CSS纯绘制）

不动的文件：
└── courseware/*.html          ← 全部课件，一个字不改
```

### 3.7 验收标准

- [ ] 平板横屏打开，看到村庄地图，不是列表
- [ ] 五个建筑区域清晰可辨，有名字标签
- [ ] 点击建筑，弹出该区域课件列表（有动画）
- [ ] Steve 在地图上会走动，点击会说话
- [ ] 进度条显示每个区域完成了几课
- [ ] 返回村庄按钮在每个课件页都能找到
- [ ] 首次打开有欢迎动画
- [ ] 加载时间 < 2秒（平板 WiFi）

## 四、进度层：成就与存档系统（Phase 2）

> 参考：`doc02_progress.md`（详细设计）

### 4.1 核心原则

**进度要"可见"，不是数字，是建筑。**
- 完成3课英语 → 学校门口多了一面旗帜
- 完成5课语文 → 图书馆多了一个书架
- 收集10颗星 → 村庄中央多了一个路灯
- 这些变化孩子**自己就会发现**，不需要弹窗告诉他

### 4.2 存档数据结构（localStorage）

```javascript
VILLAGE_STATE = {
  version: 1,
  lastVisit: 'ISO date',
  totalStars: 0,
  streakDays: 0,          // 连续学习天数
  zones: {
    english:  { completed: [], stars: {}, totalCompleted: 0 },
    chinese:  { ... },
    math:     { ... },
    songs:    { ... },
    science:  { ... }
  },
  decorations: {
    school_flag: false,       // 英语完成3课
    library_bookshelf: false, // 语文完成5课
    village_lamp: false,      // 累计10星
    bob_resident: false,      // 任意完成10课
    secret_chest: false,      // 连续3天
    rainbow: false            // 全区域各完成1课
  },
  badges: [],
  dailyMission: { date: '', task: '', reward: 0, completed: false }
}
```

### 4.3 课件完成上报协议

**对现有课件的唯一改动**：修改 `shared/courseware.js` 的 `celebrate()` 函数，在末尾追加：

```javascript
if (window.reportCourseComplete) {
  window.reportCourseComplete(calculateStars());
}
```

每个课件 `<head>` 批量插入一行：
```html
<script src="../shared/village-reporter.js"></script>
```

批量插入可用 Python 脚本自动化（约10行）。

### 4.4 装饰解锁效果

| 装饰 | 解锁条件 | 村庄变化 |
|------|---------|---------|
| 学校旗帜 | 英语完成3课 | 学校门口多一面旗帜 |
| 图书馆书架 | 语文完成5课 | 窗户里能看见新书架 |
| 村庄路灯 | 累计10星 | 村庄中央亮起路灯 |
| Bob入住 | 任意完成10课 | Bob从村外走进来，永久住村里 |
| 神秘宝箱 | 连续学习3天 | 村庄角落出现宝箱 |
| 彩虹 | 全区域各1课 | 天空出现彩虹 |

### 4.5 每日任务系统

- 任务池：完成一节英语 / 唱一首童谣 / 做三道数学题 / 读一个中文故事 / 探索科学
- 倾向于推荐孩子**最少学的区域**
- 完成后额外奖励星星
- 在村庄地图右上角展示任务板

### 4.6 连续学习天数

- 每天打开 → streakDays++
- 隔一天 → 重置为1
- 同一天多次打开 → 不变

### 4.7 验收标准

- [ ] 完成任意课件后，返回村庄能看到星星数增加
- [ ] 完成3课英语，学校门口出现旗帜（有动画）
- [ ] 第二天打开，进度还在（localStorage持久化）
- [ ] 连续2天打开，连续天数显示正确
- [ ] 每日任务显示，完成后有奖励动画

## 五、经济层：金币系统 + 每日任务（Phase 2.5）

> 参考来源：`账号管理+宠物系统.md` 中数学游戏的金币经济模型

### 5.1 设计目标

建立**学习→金币→消费→成长**的正反馈循环。数学游戏已验证：
- 答题获得金币 → 金币买食物 → 喂宠物 → 宠物成长 → 孩子有动力继续学

### 5.2 金币获取

| 行为 | 奖励 |
|------|------|
| 完成1课（任意星级） | +5 金币 |
| 完成3星课件 | +3 额外金币 |
| 完成每日任务 | +10 金币 |
| 连续学习奖励 | 随 streak 增长 |

### 5.3 金币消费

| 商品 | 价格 | 用途 |
|------|------|------|
| 宠物食物（面包） | 5 金币 | 喂宠物 |
| 宠物食物（蛋糕） | 15 金币 | 高级食物，成长更快 |
| 宠物装饰 | 20 金币 | 帽子、围巾等 |
| 村庄装饰 | 30 金币 | 额外的村庄美化 |

### 5.4 经济平衡原则

- 每天学习2-3课 → 获得 10-20 金币
- 每天喂食消耗 → 约 5-15 金币
- 净收入为正但不高，保持适度稀缺感
- **防止通货膨胀**：不设置无限刷金币的途径

## 六、情感层：宠物养成系统（Phase 3）

> 参考来源：`账号管理+宠物系统.md` 中的宠物养成机制

### 6.1 设计目标

给孩子一个**情感连接的载体**。宠物不是"功能"，是"朋友"。

### 6.2 核心机制

| 机制 | 说明 |
|------|------|
| **宠物选择** | 开局选一只我的世界风格宠物（猫/狗/鹦鹉/狐狸） |
| **喂食** | 用金币买食物喂宠物（面包/苹果/蛋糕） |
| **成长值** | 喂食积累成长值，到达阈值宠物升级/进化外观 |
| **心情值** | 根据互动频率变化，影响宠物动画表现 |
| **饥饿度** | 随时间递减，需定期喂食（但**不惩罚不喂**） |

### 6.3 宠物成长阶段

| 阶段 | 成长值 | 外观变化 |
|------|--------|---------|
| 幼崽 | 0+ | 小巧可爱 |
| 少年 | 50+ | 体型变大 |
| 成年 | 150+ | 出现装饰/特殊花纹 |
| 传说 | 300+ | 发光效果（参考附魔光泽） |

### 6.4 与村庄的集成

- 宠物在村庄地图上跟随 Steve 走动
- 宠物有状态动画：开心（蹦跳）、饥饿（趴下）、睡觉（蜷缩）
- 点击宠物 → 弹出状态面板（饱食度/成长值/心情值）
- 宠物装饰可在地图上直接看到

### 6.5 安全设计

- 宠物**不会死亡或消失**，即使长期不喂也只是"不太开心"
- 不设置时间压力或惩罚机制
- 不做排行榜或社交比较

### 6.6 验收标准

- [ ] 开局可选宠物类型
- [ ] 金币可以买食物并喂食
- [ ] 宠物有2个以上成长阶段的外观变化
- [ ] 宠物在村庄中可见、有状态动画
- [ ] 点击宠物可查看状态
- [ ] 长期不喂食，宠物不会消失

## 七、同步层：账号系统（Phase 4，可选）

> 参考来源：`账号管理+宠物系统.md` 中的账号系统实现

### 7.1 设计目标

支持多设备同步进度。数学游戏已实现：
- 注册/登录流程
- Node.js + Express 后端
- JSON 文件存储 + 每日自动备份
- PM2 进程守护

### 7.2 适用场景

- 孩子在家用平板、在学校用电脑，需要同步进度
- 家长想查看孩子的学习报告
- 多个孩子各自独立存档

### 7.3 方案对比

| 方案 | 技术栈 | 优点 | 缺点 |
|------|--------|------|------|
| A. 保持localStorage | 纯前端 | 零成本 | 换设备丢数据 |
| B. 复用数学游戏后端 | Node.js + Express | 已有代码和部署 | 需要扩数据模型 |
| C. Firebase/Firestore | Google 云服务 | 自动同步 | 需额外账号 |
| D. GitHub作为存储 | GitHub API | 免费 | 需要GitHub登录 |

### 7.4 建议

**短期**（Phase 1-3）用 localStorage，足够了。
**长期**如果绘本和数学游戏合并为统一平台，优先复用方案 B（数学游戏后端）。

## 八、叙事层：分支冒险故事（Phase 5，远期）

> 参考：`master_plan.md` Phase 3

### 8.1 设计目标

让孩子做选择、影响故事走向，从"看故事"变成"活在故事里"。

### 8.2 技术选型

- 脚本引擎：**Ink/inkjs**（MIT协议，纯文本，浏览器端运行，无需后端）
- AI生成：用 Claude/DeepSeek 批量生成分支故事脚本
- 与现有课件完全独立，是新增内容

### 8.3 推迟理由

- 优先级低于入口体验改造（孩子先得愿意"进"这个世界）
- 内容生产成本较高，可等前面阶段验证方向后再投入

---

## 九、技术约束（全局）

| 约束项 | 决策 | 理由 |
|--------|------|------|
| 部署 | GitHub Pages，纯静态 | 免费、零运维 |
| 课件格式 | 保持独立HTML，不合并 | 降低改动风险 |
| 框架 | 原生 JS + CSS，零依赖 | 维护简单，加载快 |
| 状态存储 | localStorage | 够用、无后端依赖 |
| 动画 | GSAP（已有） | 已在项目中使用 |
| 音频 | Web Speech API 兜底 + MP3优先 | 免费、浏览器原生支持 |
| 翻页引擎 | Turn.js 继续用 | ROI太低不值得换 |
| Canvas | Canvas 2D 继续用 | 齿轮/太阳系场景够用 |

---

## 十、明确排除项

| 排除 | 理由 |
|------|------|
| ❌ 重构现有115+课件内部结构 | 风险高、ROI低 |
| ❌ 引入React/Vue等框架 | 保持零依赖 |
| ❌ 做App（Godot/原生） | 网页平板体验够用 |
| ❌ 做3D我的世界 | 复杂度爆炸，2D像素风够用 |
| ❌ 做社交/排行榜 | 目标是个体使用 |
| ❌ 做付费系统 | 免费产品 |
| ❌ 做家长端后台 | 非核心需求 |

## 十一、实施节奏

```
Phase 1 → 村庄地图入口（3-5天）→ 独立可交付，验证方向对不对
   ↓
Phase 2 → 成就与存档（4-6天）→ 孩子有自己的进度
   ↓
Phase 2.5 → 金币经济（3-4天）→ 消费循环
   ↓
Phase 3 → 宠物养成（1周）→ 情感连接
   ↓
Phase 4 → 账号系统（按需）→ 多设备需求出现时再做
   ↓
Phase 5 → 分支故事（远期）→ 内容丰富后考虑
```

**总原则：每个阶段独立可交付，不依赖下一阶段。**
**最小改动验证法：Phase 1 做完后给孩子用，判断方向对不对再决定后续。**

---

## 十二、验收标准（全局）

孩子打开平板，看到的是：
1. **自己的村庄**，上次来的时候建了什么还在
2. 村庄里有几个区域，点进去是对应的课件
3. 完成课件后，村庄里有**可见的变化**（新建筑、新装饰）
4. 有自己的宠物朋友，可以用金币照顾它
5. 每次进来有**一个新的小惊喜**（宝箱、隐藏区域）
6. Steve/Alex/Bob在村庄里**会动、会说话**
